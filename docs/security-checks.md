# 安全检查

「工程 → 安全检查」展示当前项目已提交的检查任务，可打开任务查看进度、日志和报告。点击「新建检查」，按以下步骤提交：

1. **选择规则**：按分类、来源或关键词筛选，跨分类、跨页勾选；可选中全部筛选结果，切到「已选规则」集中移除。勾选多条合并为一次检查。
2. **输入目标**：填写检查名称、目标或上传附件，可补充本轮检查要求。仅从凭据中心选择目标时，可先留空目标。
3. **关联凭据中心**：在页面内直接勾选当前项目的凭据作为检查目标，支持搜索、类型及验证状态筛选，也可切到「已选凭据」集中移除。已有手动目标时可不勾选，直接进入下一步。
4. **执行配置**：配置预设 Agent、执行上限、命令守门和启动计划，确认后提交。

任务列表的「检查规则」提供独立的规则维护入口；新建检查的第一步也可维护规则。规则库全局共享；执行工程、凭据、工作目录和报告仍按项目隔离。返回上一步保留当前草稿，取消后回到检查任务列表。

安全检查统一使用内置「安全检查」指挥思路，不提供选择项；服务端也会固定该思路，忽略客户端传入的其他思路。目标可以手动输入、上传附件或从当前项目凭据中心选择；凭据不是必选项，也可以用补充要求明确检查任务。并发、轮次、Token 上限、命令守门和定时计划沿用普通工程配置。

规则库刷新不会悄悄替换已选规则版本。已选规则或凭据发生更新、下架或删除时，页面提示重新确认；点击「更新所选规则 / 凭据」后采用当前版本，移除已不存在的记录。筛选和翻页不会清除选择。

勾选凭据确定本轮检查目标，不构成凭据读取白名单。该工程的执行 Agent 可按需访问所属项目全部凭据，包括后续新增记录；指挥官只获得脱敏目录。未验证或验证失败的凭据先验证并上报，成功后用于检查。项目范围权限不会扩大本轮目标范围，也不会允许访问其他项目。

所选规则正文和版本、指挥思路、补充要求与凭据引用在提交时冻结。后续修改、同步或删除规则不改变已有工程；暂停恢复继续使用快照及工程原有的项目权限。快照不保存密码、私钥、Token 或自定义敏感字段。实际读取使用凭据中心当前版本，验证结果遵循其版本校验规则。

执行使用现有工程看板和任务会话，由 Agent 自主组织结果，通过 `engine_done` 归档到报告中心。

## 自定义与社区规则

本地自定义规则可以创建、编辑和删除。同步规则只读，点击「复制」生成独立本地副本再编辑；来源更新不会覆盖副本。

官方源默认：

- 仓库：`https://github.com/zgsfsec/Full-Chain-Sentinel-System`
- 分支：`main`
- 目录：`rules/security-checks`
- 周期：24 小时，可关闭或调整为 1–720 小时

「规则源」可添加自有 GitHub 仓库，配置分支和目录，查看同步状态、错误和最近 20 条同步记录。「同步规则」立即同步已启用来源；单个来源也可手动同步。首次启动和后续重启会补做已到期同步，同一来源不并发同步。

下载使用控制台宿主机网络，不跟随当前查看项目的代理。规则固定到一次提交 SHA 后完整校验，通过后事务替换该来源规则。同步失败保留本地已有版本，并从 5 分钟开始退避重试，最长 24 小时；其他来源不受影响。无变化时不重新下载正文。空目录、目录截断、无效规则或重复 ID 都视为同步失败。删除规则源会下架该来源规则，保留本地副本及已有工程、报告。

以 `PI_OFFLINE=1` 启动时不启动自动同步；本地规则仍可使用，手动同步仍由用户明确触发。

首版附带两条格式示例，不代表已覆盖完整等保或数据安全标准。官方目录需要随代码合入并发布到上述分支后才能从 GitHub 同步；发布前可以创建本地规则或配置已存在的规则仓库。

## 规则贡献格式

在规则源指定目录下添加 `.md` 文件，正文就是给 Agent 的自由文本提示词。该目录下的每个 Markdown 文件都必须是规则；使用说明应放到目录之外。

```markdown
---
id: linux-account-check
name: Linux 账号安全检查
category: 主机安全/Linux,等保/三级/Linux
description: 检查账号与认证配置
---

围绕操作员指定的 Linux 主机检查账号、认证与权限配置。
结合实际系统和权限自主组织只读检查，说明判断依据、无法检查的原因及整改建议。
```

`id`、`name`、`category` 必填，`description` 可选；正文非空。文件头不接受其他字段。ID 使用字母、数字、点、下划线或连字符（首字符为字母或数字），最长 128 字符。名称最长 128 字符，简介最长 1024 字符。`category` 是字符串，多个分类路径用英文逗号 `,` 分隔，也接受中文逗号；路径内仍以 `/` 表示层级。一条规则可归属最多 16 个分类，每个路径最长 256 字符，总长度最多 2048 字符；自动去重和去除分隔符周围空格，不允许空分类、空层级、`.` 或 `..`。

规则引用由「来源 ID + 规则 ID」组成，不同仓库相同 ID 不互相覆盖；同一来源内部不可重复。移动文件或改变分类时保留 ID。规范化内容的 SHA256 摘要作为版本，无需手工维护版本号。

每条规则最大 128 KiB，每个来源最多 1000 条，单次同步正文总量最大 16 MiB。同步只处理普通 Markdown 文件，不执行仓库脚本；GitHub 限流或访问受限会显示具体错误。

规则应描述检查目标、约束及交付要求，不包含真实客户数据或凭据。明确哪些检查只读、所需权限及无法确认时的处理方式，不要求 Agent 编造证据或作出超出实际覆盖面的合规结论。

## 本地存储

全局规则与同步配置位于配置目录的 `security-checks.db`；工程快照位于现有 `engines.db` 的 `engine_submissions`，执行输入写入项目的 `.sentinel/engine-inputs/<engine-id>/input.json`，文件权限为 `0600`。凭据继续由原有加密凭据中心管理，不复制到规则库。
