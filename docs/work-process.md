# 工作链路

工作链路根据用户指令、可见 Agent 消息和工具记录，重建目标、工作步骤、结果及转向依据。它独立于监督，每个对话或工程单独开启。分析不会向执行 Agent 注入指令。

## 使用

1. 在「设置 → 模型 → 角色分配」选择工作链路模型；默认跟随主模型。
2. 打开左侧「执行与审计 → 工作链路」，选择项目及「对话 / 工程」。也可以从对话或工程页面右上角的「工作链路」进入。
   对话输入框上方「监督」右侧也有「工作链路」按钮：点击即开启当前对话的持续记录，并打开链路抽屉。已有记录会补分析，后续记录持续更新；关闭抽屉不会停止记录，可在详情中暂停。再次查看已开启的链路不会重启在途分析。
3. 进入对象详情后选择：
   - **开启工作链路**：分析已有记录，并持续处理新增记录。
   - **补分析已有记录**：处理当前已有记录；未开启持续分析的对象不会因此自动开启。
   - **暂停分析**：取消当前分析，保留已有结果。恢复后补齐遗漏记录。
   - **重试分析**：从尚未成功分析的记录继续；失败原因显示在详情上方。
   新建工程或安全检查时，也可以在最后一步「执行配置」勾选「记录工作链路」，默认关闭。勾选后在指挥官启动前开启本工程的记录，覆盖指挥、任务和子 Agent；定时工程从保存时开始记录，执行仍按计划时间启动。每日新一轮沿用上一轮当时是否开启记录的状态。记录开启失败会写入工程指挥日志，可在工作链路页面手动开启。
4. 在「目标树」查看目标归属层级；「链路图」根据先后、依赖、转向与汇合关系从左向右分层，同级步骤也可沿工作关系展开，并行分支分行、汇合进入后续层。循环关系保留为回连，不修改原始目标归属。缺少工作关系时按目标归属排列，不编造路径。支持拖动画布、适应视图、缩放、定位选中节点、关系筛选、搜索及分支收起。选中节点时突出相关路径。大图每组展示最多 150 个节点，节点详情保留全部关联。
   链路图默认显示工作流及分支入口，避免总目标到每一步的归属连线遮挡路径；可切换「全部关系」查看完整连接。分支围绕主线向上、向下排列，汇合后重新对齐；跨列和回连寻找附近空隙绕行。初次浏览垂直居中，适应视图时整体居中。
5. 点击节点查看意图、行动、结果及证据。详情栏独立滚动，关闭按钮固定；点击原始记录自动定位到对应内容。窄屏下图谱和详情上下排列，均可滚动。原始记录按真实会话条目或工程事件定位；模型节点还可查看修订历史。
6. 点击详情顶部「新页面展开」，在新标签页独立查看当前对话或工程的链路，默认显示链路图，并保留打开时选中的节点。独立页面没有控制台侧栏，可点击「进入全屏」进一步铺满屏幕，按 Esc 或点击「退出全屏」恢复；「返回控制台」回到普通界面。浏览器要求在新页再次点击才能进入全屏；不支持全屏时仍可使用独立页面。刷新保留链路对象及链接中的节点。展开、全屏和关闭页面不会改变持续记录状态。

工程视图汇总总目标、指挥 Agent、所属任务和任务内部步骤。失败及放弃的路径保留。步骤按工作目的聚合，多次工具调用可以属于同一步骤。

`spawn_agent` 的子 Agent 会作为独立分支记录，挂在所属对话或工程任务下。派发任务、工具调用、可见消息、运行状态和最终结果从保留的子 Agent 数据库读取，每个子 Agent 单独分析，避免和主 Agent 或并行子 Agent 的步骤混合。开启父对象的工作链路后自动纳入这些分支；已有子 Agent 记录也可补分析，无需单独开启。原始记录按所属项目、父会话和子 Agent 定位，不读取隐藏思考。

## 事实与推断

- 结构性归属与派发关系来自工程记录，使用实线。
- 模型推断的目标归类和关系使用虚线。
- 意图区分「明确表达」「模型推断」「无法判断」。明确表达必须引用对应可见原文。
- 置信度是模型自评，不能视为准确率。
- 先后关系不等于因果关系；推断依赖或转向必须附证据引用。
- 不读取隐藏思考。工具调用开始记录不代表完成；没有返回结果时不能仅凭该调用宣称完成。
- 原始记录已截断时会标注证据不完整。记录缺失时不会补造原文。模型仍可能解释错误，应结合证据核对。

## 更新与保存

服务每 3 秒检查开启对象的新增记录。每批最多 12 条，同一对象串行，全局最多两个分析请求。持续运行中的小批记录最多每 15 秒分析一次；手动补分析和首次开启的历史补齐直接排队处理。页面详情每 3 秒刷新，列表每 5 秒刷新。

分析通过 pi SDK 使用工作链路模型配置的最大输出额度。遇到模型输出截断时，自动将批次减半；单条记录仍截断则再尝试精简输出。缩批和精简模式会保存，后续分析及服务重启后继续使用。单条精简输出仍失败则结束本轮，进入退避重试，显示模型、输出 token 数和配置建议。每轮分析及其缩批尝试共用 180 秒期限，截断结果不会入图或推进进度。

图谱、已消费记录的指纹及修订在 `<配置目录>/work-process.db` 中以事务保存。重试和服务重启不会重复消费成功分析过的记录。分析失败（包括网络失败、超时、输出校验失败及缩批后仍截断）自动按 3、6、12、24、48 秒间隔重试，此后每 60 秒重试一次，直到成功或手动暂停。失败结果不会入图或推进记录进度；重试等待期间不占模型并发名额。详情显示最近原因、重试次数和下次重试时间；上次失败原因随输入反馈，供模型修正输出。历史补分析也按相同策略恢复，且不会自动开启持续分析。重试计划保存到数据库，重启后恢复；已有开启对象的历史错误在启动时纳入重试。暂停或删除时取消在途请求和重试计划，迟到响应不再写入。删除对话、工程或项目数据时清理其工作链路。

模型输入分别标明本批可用证据 ID 和已有节点的历史引用。更新已有节点时，服务端自动保留历史证据，也允许模型一并返回属于该节点、且可核验的旧引用。每个更新节点仍须显式引用本批记录，所有本批记录都必须被覆盖；未知引用、跨节点挪用旧证据和只返回历史引用均不通过校验。

摘要和原文查看均执行已有的凭据脱敏。分析使用配置的工作链路模型端点，会产生独立的模型调用和 token 消耗，详情用量包含已返回响应的分析尝试，包括截断或校验失败的响应。也可以点击「重试分析」立即重试，或暂停以停止自动调用。

## 实现与验证

- `packages/web/src/work-process-source.ts`：只读来源适配及原始记录定位。
- `packages/web/src/work-process-analysis.ts`：分析输入、提示词和输出引用校验。
- `packages/web/src/work-process.ts`：独立后台队列、增量处理及取消。
- `packages/web/src/work-process-store.ts`：SQLite 图谱、进度、持续分析索引及修订。
- `packages/web/src/work-process-api.ts`：复用现有入口、登录和使用确认校验的 HTTP 接口。
- `packages/web/webui/src/components/WorkProcessPage.tsx`：列表、详情、操作及证据查看。
- `packages/web/webui/src/components/WorkProcessGraph.tsx`：目标树和链路图。
- `packages/web/webui/src/components/WorkLinkFullPage.tsx`：独立链路页面及浏览器全屏。

专项测试从 `packages/web` 运行：

```sh
node ../../node_modules/vitest/dist/cli.js --run test/work-process.test.ts test/work-process-source.test.ts test/work-process-server.test.ts webui/src/components/WorkProcessPage.test.tsx webui/src/work-link-page.test.tsx
```

测试使用本地模拟模型和模拟 Docker，覆盖引用校验、节点稳定性、批次消费、失败重试、暂停取消、重启恢复、并发限制、工程汇总、登录隔离、真实 SDK 协议调用和新增消息的后台增量处理。页面另外验证目标树、链路图、证据、修订、搜索、折叠、缩放、窄屏及深色模式。
