# WebFuzz 手动发包

侧栏「资产与工具 → MITM 中心」下方的 WebFuzz 是操作员的 HTTP/1.1 手动重发工作台。编辑原始请求、点击发送，在右侧查看状态、响应头、正文和各阶段耗时。首版不提供字典爆破、批量变异或 Agent 自动调用。

## 使用

1. 选择项目，打开 WebFuzz。在左侧请求头填写 `Host`，例如 `Host: example.com:8443`；路径和参数写在请求行中。上方勾选「HTTPS」启用 TLS，取消勾选则使用 HTTP，不需要另外填写目标地址。Host 没有端口时，HTTPS 使用 443，HTTP 使用 80；显式端口优先。支持中文域名和带方括号的 IPv6。MITM 导入和历史恢复会保留原来的协议。
2. 编辑 UTF-8 文本请求。上方显示从 Host 识别出的目标；修改 Host 后实际连接地址随之更新。缺失、重复或无效的 Host 会阻止发送。请求头规范为 CRLF；默认更新 Content-Length，可在发送选项中关闭。Transfer-Encoding 存在时保留原有长度头。原始二进制请求和手动 CONNECT 隧道暂不支持。请求与响应长行会在面板内自动折行，请求行号按原始行对齐；视觉折行不会改变报文内容。
3. 选择网络出口，点击「发送请求」。不会自动跟随重定向、解压响应或重试，也不会执行响应中的 HTML / JavaScript。响应可切换报文、正文、响应头，支持查找、复制和 JSON 格式化；压缩或二进制正文以 Base64 显示。「报文」保留实际收到的 HTTP 字节，包括 chunked 分块及尾部字段；旧记录若未保存原始响应，会提示重新发送。查找会滚动到匹配处，可用按钮或 Enter / Shift+Enter 切换位置。
4. 可新建、复制、命名和关闭标签。点击标签标题（如「未命名请求」）或旁边的编辑图标可修改名称；Enter 或点击别处保存，Esc 取消，最多 80 个字符。标题与请求名称输入框同步，随草稿自动保存。当前项目最多保留 20 个标签。右上角历史记录保留最近 30 次已完成的发送，含失败结果；点击记录恢复到新标签，需要再次点击发送才会发包。

在 MITM 中心打开流量详情，点击「发送到 WebFuzz」可将完整的 UTF-8 请求导入当前项目。已截断、缺失或二进制请求会拒绝导入，避免把不完整报文当作原始请求发送。导入本身不访问目标。

## 网络出口

| 选择 | 行为 |
| --- | --- |
| 项目代理（默认） | 使用当前项目工作容器的网络命名空间，跟随项目的透明代理、网关或 VPN。工作容器必须运行；失败不会回退到直连。没有配置代理的项目使用项目自身网络。 |
| 直连 | 使用独立 Docker bridge 网络，不经过项目的代理或 VPN；Docker 主机自身的网络规则仍然有效。不需要工作容器运行。 |
| MITM 留痕 | 经当前项目已启动的 MITM 代理发送，遵循该项目的静态过滤与抓包上限。MITM 未启动时拒绝发送，不会自动启动。此出口使用 MITM 自身网络，不叠加项目上游代理。 |

MITM 开启账号认证时，需在页面输入代理密码。密码仅用于本次代理连接，不写入草稿、发送历史、环境变量或命令行参数。认证头在发给目标和保存抓包之前由 MITM 移除。HTTPS 模式会向临时发包容器提供该项目的 CA 公钥证书，无需关闭 TLS 校验；CA 私钥不挂载给发包容器。自签名目标可按需开启「忽略 TLS 证书错误」，默认关闭。

该开关仅控制 WebFuzz 发包端的 TLS 校验；选择 MITM 出口时，不会改变 MITM 代理对目标证书的校验设置。

## 限制与数据

- 使用现有 `sentinel:latest` 工具镜像及对应架构的 `replayd` 二进制，不新增镜像依赖。每次发送使用临时容器，仅挂载只读发包引擎和可选 CA 公钥证书，不挂载工作目录、抓包数据库或 CA 私钥，不发布端口。
- 超时可设为 1–120 秒，默认 30 秒。发送完成、失败或取消后清理临时容器；控制台意外退出时，临时容器最多运行约 180 秒后自动退出。每个项目最多同时处理 4 次发送。
- 单次请求最多 512 KB。响应正文和原始报文各最多预览并保存 128 KB，响应头最多保存约 32 KB，超出会提示预览截断；响应大小保留引擎实际读取值（引擎正文接收上限为 64 MB）。预览截断与连接中断会分别提示；对端提前关闭连接时显示接收错误，并保留已经收到的部分。大响应不会完整写入 WebFuzz 历史。MITM 代理转发采用流式传输，不受该 WebFuzz 接收上限限制。
- 请求经过 TLS/网络连接及容器启动需要时间；页面显示的连接、TLS、首字节和总耗时来自发包引擎，不包含临时容器准备时间。
- 切换页面、项目或取消发送会取消当前页面的请求并清理临时容器；取消不会撤回已经发给目标的数据。取消的请求不新增发送历史，但经过 MITM 的已发送流量仍可能留痕。
- 草稿和历史存放在配置目录 `mitm/<项目 ID>/webfuzz.db`，与当前抓包目录分开。清空 MITM 数据包不会删除 WebFuzz 草稿或历史；删除项目数据会一并清理。
- WebFuzz API 复用控制台入口、登录、授权声明及当前项目校验，不向 Agent 开放。远程 Docker 仍要求发包引擎及可选 CA 公钥证书的挂载路径在 Docker 主机上可用。
