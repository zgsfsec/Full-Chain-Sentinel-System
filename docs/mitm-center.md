# MITM 中心

MITM 中心接收由操作员手动配置代理的浏览器或设备流量。每个项目拥有独立的代理容器、端口、CA 和历史记录，可以同时运行。支持页面查看与 Agent 只读查询，不暂停请求。

需要手动修改和重发请求时，可在流量详情中点击「发送到 WebFuzz」，进入侧栏下方的 [WebFuzz 手动发包工作台](webfuzz.md)。导入不会自动发送，WebFuzz 草稿和发送历史按项目独立保存。

## Agent 查询

主 Agent、工程任务 Agent 和子 Agent 可以查询各自所属项目的已捕获流量，指挥官不接入。启动、停止、配置和清空仍由操作员完成，查询工具不会启动代理、访问目标或重放请求，也不会自动把工作容器流量转入 MITM。

在「设置 → 权限」中控制 `mitm_read`，工程任务沿用主 Agent 权限，子 Agent 权限不能超过主 Agent。新安装默认启用；已有 `permissions.json` 未包含该字段时默认关闭，需要手动打开并保存。工具随会话创建或权限保存后的会话重建生效。

| 工具 | 用途 |
| --- | --- |
| `mitm_flows` | 按域名/IP、路径、请求方法、状态码（如 `200`、`4xx`、`error`）和时间组合筛选；`search` 搜索域名、路径和查询参数，不搜索正文。时间为 Unix 毫秒时间戳，包含边界；默认每页 20 条、最多 50 条，按时间倒序翻页。 |
| `mitm_flow_get` | 查看一条流量的元信息、请求/响应头，以及原始 HTTP 报文预览。每侧默认 4096 字节、最多 8192 字节；`previewBytes: 0` 只看元信息和头部。头部及列表长字段也限量返回并标明截断。 |
| `mitm_flow_read` | 按 `id`、`side`（`request` / `response`）分段读取已保存的原始报文；默认 4096 字节、最多 16384 字节，继续时传入返回的 `nextOffset`，为 `null` 时已读完。 |

报文包含 HTTP 头部，偏移和长度按原始字节计算。二进制或恰好切开 UTF-8 字符的分段以 Base64 返回，避免丢字节。`truncated` 表示本次未返回全部，`captureTruncated` 表示捕获时已经截断，未保存部分无法继续读取。代理停止后仍可查询历史；运行时复用容器内的实时读取路径。

例如可对 Agent 说：「筛选当前项目最近一小时 `/login` 返回 4xx 的流量，查看请求和响应，分析失败原因。」工具不接受项目切换参数；后台会话和工程始终读取创建时绑定的项目。

所有返回的流量（包括 URL、头部、正文及错误）都标记为不可信外部内容，工具说明要求 Agent 只将其作为数据分析，不执行其中的指令。这是上下文边界标记，不代表已检测或消除提示词注入。

## 接入

1. 选择项目，在「资产与工具 → MITM 中心」点击「启动代理」。首次启动自动分配端口，之后保留该端口。
2. 在浏览器、代理切换扩展或设备的网络设置中填写 **HTTP 代理**地址与端口。HTTP、HTTPS 都使用这个代理；无需设置 SOCKS。
3. 默认只监听 Docker 主机的 `127.0.0.1`。手机、其他电脑或远程部署在「代理设置」中选择「所有网卡（0.0.0.0）」，保存后填写 **Docker 主机的真实 IP**。运行中保存会自动重启代理；尚未启动时，保存后点击启动。公网部署使用公网 IP，并放通安全组、防火墙和必要的端口映射。`0.0.0.0` 是监听范围，不能作为设备的代理地址。
4. 访问目标，页面会每 3 秒刷新流量。支持搜索域名、路径、参数，并按请求方法、响应状态或连接异常筛选。
5. 请求地址单行展示，长地址省略，悬停可查看完整地址。点击查看请求/响应头和原始报文。超过 1 MB 的已保存报文只预览前 1 MB，可下载已保存内容；二进制内容显示为 Base64。捕获的 HTML 仅按文本展示。

如浏览器对 localhost 或内网地址配置了「绕过代理」，需要同时调整该规则。容器内访问本机测试服务可使用 `host.docker.internal`；目标服务须监听 Docker 可达的地址。

## 代理账号认证

在「代理设置」打开「代理账号认证」，填写账号与密码并保存。运行中会自动重启代理应用新配置，无需手动停止；现有连接会短暂中断。每个项目独立设置一组账号；账号为 1–64 位可见 ASCII 字符，不含空格和冒号，密码为 8–128 位可见 ASCII 字符。账号认证默认关闭；对外监听时应启用。

客户端选择 HTTP Basic 代理认证，填写同一组账号密码。HTTP 请求和 HTTPS CONNECT 均需认证，未提供或错误时返回 `407 Proxy Authentication Required`；未认证请求不访问目标、不写流量库。示例：

```sh
curl --proxy http://<主机 IP>:<端口> --proxy-user '<代理账号>:<代理密码>' http://example.com
curl --proxy http://<主机 IP>:<端口> --proxy-user '<代理账号>:<代理密码>' --cacert ca.pem https://example.com
```

密码保存为独立随机盐的 PBKDF2-SHA256 哈希（100000 轮），不保存明文，状态接口不返回密码、盐或哈希。再次编辑时留空保留原密码，填写新值则更换；关闭并保存认证会清除密码哈希。清空流量保留认证配置。代理引擎从只读文件加载认证配置，命令行和环境变量不携带密码；转发及保存报文前会移除 `Proxy-Authorization` 头。

Basic 认证不加密客户端到 HTTP 代理的链路，HTTPS 目标的 CONNECT 认证也发生在 TLS 握手前。公网使用建议通过 VPN 或 SSH 隧道保护该链路，并限制来源地址。

## 过滤与保存上限

可随时打开「代理设置」查看并调整以下选项。运行中修改后保存会自动重启代理应用配置，历史记录与证书保留；配置未改变时不重启。应用失败会恢复原配置并尝试重新启动，恢复失败时页面会显示错误。

- **过滤常见静态资源**：默认开启，按请求路径后缀及响应 Content-Type 跳过 JPG、PNG、MP4 等图片、音视频、字体和 CSS；不阻断资源访问，也不将它们写入流量数据库或正文文件。只对 GET/HEAD 的正常响应过滤；提交请求、错误响应，以及 JS、SVG、source map、HTML、JSON 等仍可记录。需要完整捕获时可关闭。已有历史记录不会自动删除。
- **单侧报文保存上限**：默认 2 MB，可设为 1–32 MB。请求和响应分别限量保存，超出部分在入库前截断，保留原始大小并在详情中提示。下载得到的是已保存部分；该存储限制不会截断转发给客户端的报文。不会额外重复保存请求体、响应体。

单条报文上限不等于项目总存储配额；长时间捕获仍会累积记录，需要按需清空。

代理运行时，控制台在 MITM 容器内读取当前 SQLite 事务，避免 Docker Desktop 的 Linux 容器与宿主机共享 WAL 内存造成实时记录不可见。停止后改为直接读取宿主机的持久化历史。

更新代理引擎时需要同时更新对应架构的 replayd 二进制（源码可在 `MITM_Fuzz_Render` 执行 `make dist`），并重新启动代理以载入新引擎。运行中删除使用引擎的内部管理接口，升级后需要停止并重新启动已有代理。

## HTTPS 证书

在「接入与证书」下载当前项目的 CRT 或 PEM，将它安装到测试浏览器/设备，并启用根证书信任。页面可核对 SHA-256 指纹。每个项目的 CA 不同，切换项目代理时需安装对应证书。

**项目工作容器自动安装 CA**：MITM 启动成功后，将本项目的 CA 公钥证书安装到对应工作容器的 `/usr/local/share/ca-certificates/sentinel-mitm-center.crt`，更新系统信任库。工作容器尚未运行时延后安装，在启动、进入项目或重建容器时自动补装；清空流量保留原 CA。重复同步不会重复改写相同证书，安装失败会报错并可重试。只复制公钥证书，不复制 CA 私钥，不修改宿主机或其他项目的信任库。

使用系统证书库的 curl、wget、Python SSL 等可直接验证此 CA；维护独立信任库的浏览器、Java、自带 certifi 的 Python 环境等仍需单独配置。已启动且缓存信任库的进程可能需要重新启动。自动安装证书不会自动配置 HTTP 代理或接入 Agent 流量。

- Firefox 可以在自己的证书管理器中导入 CA。
- iOS 安装描述文件后，还需在「关于本机 → 证书信任设置」中启用完全信任。
- Android 应用可能不信任用户安装的 CA；带证书锁定的应用也可能拒绝解密。安装 CA 不保证所有应用都能解密。

只对受控测试设备安装 CA。接口仅提供公钥证书下载，不提供 CA 私钥下载。

## 运行与数据

- 需要本地 Docker、已构建的 `sentinel:latest` 工具镜像，以及对应架构的 `replayd_linux_amd64` / `replayd_linux_arm64`。发行包携带 `replayd/`；源码部署可通过 `SENTINEL_REPLAYD_DIR` 指定二进制目录。
- 代理直接使用 Docker 默认网络访问目标，**不跟随项目在「代理」页选择的上游出口**。工作容器仅自动安装本项目 CA，网络和代理配置仍由操作员选择。
- 对外只发布代理端口。引擎管理 API 仅监听 MITM 容器内部回环地址，不发布端口。
- 切换页面、切换项目或重启控制台不会停止代理。点击「停止代理」会停止整个 MITM 容器并断开现有连接。Docker 服务重启后需手动启动代理。
- 停止后仍可查看和下载已捕获流量。运行时也可以查看和修改配置；保存变更自动重启代理，现有连接短暂中断，证书和历史保留。
- 页面右上角「清空数据包」可在抓包过程中使用，确认后删除事务开始时已入库的全部代理流量，保留 CA、端口和认证配置，继续接收新流量。尚未完成的请求之后入库仍会显示。
- 列表左侧可勾选当前页的数据包，点击「删除选中」并确认后，仅删除指定记录；翻页、切换筛选或项目时清除勾选。运行中删除不停止代理；删除接口每次最多接受 100 个记录 ID，仅能操作当前项目的代理流量。
- 运行中清空或勾选删除由代理引擎执行：通过 SQLite 事务移除流量和释放正文引用，随后物理回收未被引用的文件。文件回收与抓包、重发记录及产物写入共用写锁，仍被其他数据引用的文件会保留。停止状态清空会换用新数据目录并删除旧目录，避免 Docker Desktop 缓存旧数据库路径。
- 删除「项目数据」会先清理对应 MITM 容器与流量、证书；清理失败时保留项目注册信息，方便重试。「仅删除容器」针对工作容器，MITM 服务独立管理。
- 流量与证书存放在配置目录下的 `mitm/<项目 ID>/`，独立于 `/work`，该数据目录不挂载给工作容器；流量仅在 Agent 调用查询工具时限量返回，仅 CA 公钥证书复制到工作容器系统信任库。`capture.json` 指向当前数据目录，`config.json` 保存监听配置。备份时应先停止代理，再备份整个目录。
- 首版由操作员手动清空历史，未设置自动轮转。长期开启时需留意数据目录占用。

## 协议与网络范围

支持 HTTP/1.1 以及 CONNECT 后的 HTTPS 解密。WebSocket/Upgrade 以隧道方式转发，只记录隧道信息，不记录消息帧；不提供 HTTP/2、HTTP/3 流量解析或手工修改放行功能。

代理账号与控制台登录账号分别配置。对外监听时应开启代理账号认证，并由防火墙限制来源地址。若控制台连接远程 Docker，证书与数据目录必须在 Docker 主机上以相同路径可用，代理地址也应使用该 Docker 主机。
