# MITM 中心

MITM 中心接收由操作员手动配置代理的浏览器或设备流量。每个项目拥有独立的代理容器、端口、CA 和历史记录，可以同时运行。首版提供流量查看与筛选，不暂停请求，不接入 Agent。

## 接入

1. 选择项目，在「资产与工具 → MITM 中心」点击「启动代理」。首次启动自动分配端口，之后保留该端口。
2. 在浏览器、代理切换扩展或设备的网络设置中填写 **HTTP 代理**地址与端口。HTTP、HTTPS 都使用这个代理；无需设置 SOCKS。
3. 默认只监听 Docker 主机的 `127.0.0.1`。手机、其他电脑或远程部署需先停止代理，在「代理设置」中选择「允许局域网设备」，保存并启动，然后填写 **Docker 主机的真实 IP**。`0.0.0.0` 是监听范围，不能作为设备的代理地址。
4. 访问目标，页面会每 3 秒刷新流量。支持搜索域名、路径、参数，并按请求方法、响应状态或连接异常筛选。
5. 请求地址单行展示，长地址省略，悬停可查看完整地址。点击查看请求/响应头和原始报文。超过 1 MB 的已保存报文只预览前 1 MB，可下载已保存内容；二进制内容显示为 Base64。捕获的 HTML 仅按文本展示。

如浏览器对 localhost 或内网地址配置了「绕过代理」，需要同时调整该规则。容器内访问本机测试服务可使用 `host.docker.internal`；目标服务须监听 Docker 可达的地址。

## 过滤与保存上限

停止代理后，可在「代理设置」调整以下选项，保存并重新启动后生效：

- **过滤常见静态资源**：默认开启，按请求路径后缀及响应 Content-Type 跳过 JPG、PNG、MP4 等图片、音视频、字体和 CSS；不阻断资源访问，也不将它们写入流量数据库或正文文件。只对 GET/HEAD 的正常响应过滤；提交请求、错误响应，以及 JS、SVG、source map、HTML、JSON 等仍可记录。需要完整捕获时可关闭。已有历史记录不会自动删除。
- **单侧报文保存上限**：默认 2 MB，可设为 1–32 MB。请求和响应分别限量保存，超出部分在入库前截断，保留原始大小并在详情中提示。下载得到的是已保存部分；该存储限制不会截断转发给客户端的报文。不会额外重复保存请求体、响应体。

单条报文上限不等于项目总存储配额；长时间捕获仍会累积记录，需要按需清空。

代理运行时，控制台在 MITM 容器内读取当前 SQLite 事务，避免 Docker Desktop 的 Linux 容器与宿主机共享 WAL 内存造成实时记录不可见。停止后改为直接读取宿主机的持久化历史。

更新本功能时需要同时更新对应架构的 replayd 二进制（源码可在 `MITM_Fuzz_Render` 执行 `make dist`）。已经运行的 MITM 代理需停止并重新启动一次，以载入新引擎和保存配置。

## HTTPS 证书

在「接入与证书」下载当前项目的 CRT 或 PEM，将它安装到测试浏览器/设备，并启用根证书信任。页面可核对 SHA-256 指纹。每个项目的 CA 不同，切换项目代理时需安装对应证书。

**项目工作容器自动安装 CA**：MITM 启动成功后，将本项目的 CA 公钥证书安装到对应工作容器的 `/usr/local/share/ca-certificates/sentinel-mitm-center.crt`，更新系统信任库。工作容器尚未运行时延后安装，在启动、进入项目或重建容器时自动补装；清空流量保留原 CA。重复同步不会重复改写相同证书，安装失败会报错并可重试。只复制公钥证书，不复制 CA 私钥，不修改宿主机或其他项目的信任库。

使用系统证书库的 curl、wget、Python SSL 等可直接验证此 CA；维护独立信任库的浏览器、Java、自带 certifi 的 Python 环境等仍需单独配置。已启动且缓存信任库的进程可能需要重新启动。自动安装证书不会自动配置 HTTP 代理或接入 Agent 流量。

- Firefox 可以在自己的证书管理器中导入 CA。
- iOS 安装描述文件后，还需在「关于本机 → 证书信任设置」中启用完全信任。
- Android 应用可能不信任用户安装的 CA；带证书锁定的应用也可能拒绝解密。安装 CA 不保证所有应用都能解密。

只对受控测试设备安装 CA。接口仅提供公钥证书下载，不提供 CA 私钥下载。

## 运行与数据

- 需要本地 Docker、已构建的 `sentinel:latest` 工具镜像，以及对应架构的 `replayd_linux_amd64` / `replayd_linux_arm64`。发行包携带 `replayd/`；源码部署可通过 `SENTINEL_REPLAYD_DIR` 指定二进制目录。
- 代理直接使用 Docker 默认网络访问目标，**不跟随项目在「代理」页选择的上游出口**。工作容器仅自动安装本项目 CA，网络和代理配置仍由操作员选择。
- 对外只发布代理端口。引擎管理 API 仅监听 MITM 容器内部回环地址，不发布端口。
- 切换页面、切换项目或重启控制台不会停止代理。点击「停止代理」会停止整个 MITM 容器并断开现有连接。Docker 服务重启后需手动启动代理。
- 停止后仍可查看和下载已捕获流量。配置只能在停止状态修改。
- 「清空记录」需要先停止代理并确认；会删除当前项目全部流量，保留 CA 和端口。清空后的再次启动使用新的数据目录，避免 Docker Desktop 缓存旧数据库路径。
- 删除「项目数据」会先清理对应 MITM 容器与流量、证书；清理失败时保留项目注册信息，方便重试。「仅删除容器」针对工作容器，MITM 服务独立管理。
- 流量与证书存放在配置目录下的 `mitm/<项目 ID>/`，独立于 `/work`，该数据目录不挂载给工作容器，也不会自动加入 Agent 上下文；仅 CA 公钥证书复制到工作容器系统信任库。`capture.json` 指向当前数据目录，`config.json` 保存监听配置。备份时应先停止代理，再备份整个目录。
- 首版由操作员手动清空历史，未设置自动轮转。长期开启时需留意数据目录占用。

## 协议与网络范围

支持 HTTP/1.1 以及 CONNECT 后的 HTTPS 解密。WebSocket/Upgrade 以隧道方式转发，只记录隧道信息，不记录消息帧；不提供 HTTP/2、HTTP/3 流量解析或手工修改放行功能。

代理端口没有账号认证。启用局域网监听时，应由防火墙限制来源地址；不要直接发布到公网。若控制台连接远程 Docker，证书与数据目录必须在 Docker 主机上以相同路径可用，代理地址也应使用该 Docker 主机。
