# 报告中心

侧栏「资产与工具 → 报告中心」按项目归档 Agent 提交的 Markdown 报告和证据图片。普通会话、自主目标、工程任务和工程总报告均可归档，并保留提交时的会话或工程信息。

## 提交与结束任务

普通会话和自主目标通过 `report_submit` 主动提交。系统提示词要求 Agent 完成实质测试任务时先上报已确认的漏洞，再提交报告，成功后正常结束或调用 `goal_complete`。普通问答、短解释和中间进度不生成报告。

这是由提示词引导的 Agent 行为，不会拦截普通会话的每次最终回复，也不会在每轮自动生成报告。用户可以直接要求 Agent「完成后提交报告到报告中心」。

工具参数：

| 参数 | 说明 |
| --- | --- |
| `title` | 必填，1–120 个字符的单行标题 |
| `markdown` | 完整 Markdown 正文，与 `path` 二选一 |
| `path` | 项目工作目录内已有的 Markdown 文件路径，例如 `/work/reports/final.md` |

```json
{
  "title": "接口访问控制测试报告",
  "path": "/work/reports/final.md"
}
```

工程指挥官通过原有 `engine_done` 提交总报告。系统会先归档报告和图片，再把工程标记为完成；归档失败时返回具体错误，工程保持运行，修正后可以重试。已有的工程内总报告仍可查看。

报告应说明实际范围、方法、证据、结论、漏洞中枢引用、限制和建议。没有确认漏洞也可如实提交，不应把受阻或未完成的工作写成成功。

## 图片归档

使用标准 Markdown 图片语法，支持直接引用和引用式图片；代码块里的示例不会被当成证据图片。

```markdown
![接口响应](../evidence/response.png)
```

- 使用 `path` 提交时，相对图片路径按 Markdown 文件所在目录解析。
- 使用 `markdown` 或 `engine_done` 提交时，相对图片路径按项目 `/work` 解析。
- 支持 `/work/...`、项目目录内的宿主机路径，以及 base64 内联图片。
- 外链图片需要先下载到项目工作目录，再使用本地路径引用。
- 图片文件必须位于所属项目内；不能通过路径或符号链接读取项目外文件。
- 支持 PNG、JPEG、GIF、WebP、BMP、SVG。正文最多 1 MB，每张图片最多 8 MB，每份最多 64 张，正文与图片合计最多 32 MB。

正文和图片一次性归档。任何一张图片缺失或不合要求时，整份提交失败，不会留下缺图报告。成功后图片保存在控制台的 `reports.db`，停止、重建或删除项目容器不会让已归档图片失效。

## 查看、编辑、下载与删除

报告中心跟随全局项目选择，不再单独切换项目。支持按标题或关联会话／工程搜索、按来源筛选和分页。打开报告后可切换渲染预览与 Markdown 源文，点击图片放大查看。

点击「编辑」进入左右分栏：左侧修改标题与 Markdown 正文，右侧实时预览，窄屏时上下排列。点击「保存修改」更新报告；取消编辑或返回列表时，如有未保存的修改，会先提示是否放弃。编辑期间刷新报告不会覆盖草稿。浏览器支持会话存储时，切换项目或离开页面后重新打开同一报告，会恢复该标签页内未保存的草稿。

编辑保留已有归档图片，图片路径不变即可继续预览和下载，不依赖项目原文件。当前编辑器不上传新图片，新增未归档图片引用时会提示修正。多窗口修改同一报告时，保存会校验原始版本；出现冲突会保留当前草稿，需复制草稿、取消编辑并刷新后合并修改。修改报告中心的归档副本不会改写会话记录或工程内的原始总报告。

没有图片时下载 `.md`；有图片时下载 `.zip`，包含 `report.md` 和 `images/`，正文中的图片路径自动改成包内相对路径。解压后可以离线阅读。

删除报告需要确认，并同时删除归档图片。删除项目时，如果同时删除项目数据，该项目报告也会清理；仅删除容器时保留报告。

报告和图片接口沿用控制台的登录、授权承诺校验，并按项目限定读取和删除。Markdown 预览不执行原始 HTML，只加载已归档图片。
