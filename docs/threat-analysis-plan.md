# 威胁反制：架构与实现说明

入口为“情报 → 威胁反制”。平台接收设备告警，工程仅接收威胁 IP 列表，按指挥思路生成关联分析及防御建议。设备接入协议和默认值见 [接入指南](threat-intelligence.md)。

## 业务规则

| 项目 | 实际行为 |
| --- | --- |
| 接入 | 统一 JSON 主动推送，设备转换格式；每数据源独立 Token |
| 隔离与去重 | 项目内按规范化 IP 合并，保留来源与告警元数据；跨项目独立 |
| 触发 | 累计符合条件的未处理去重 IP 达到阈值，按配置的批大小、并发创建独立工程 |
| 指挥思路 | 直接关联“工程 → 指挥思路”，默认内置“威胁溯源反制”；每批冻结最新内容和策略 |
| 冷却 | 从选入批次开始；冷却结束且有未覆盖新告警才再次入池 |
| 并发 | 同 IP 同时只属于一个批次；暂停批次占容量，失败批次保留 IP 占用等待人工处理 |
| 成功 | 普通工程 completed、非空报告归档且成功任务覆盖全部批次 IP 后整批成功 |
| 失败 | 手动重试创建新尝试与工程，使用原快照；或放弃原快照 |
| 校验 | 一条记录无效或 ID 内容冲突则整批拒绝，事务回滚 |
| 保留 | 告警元数据永久保存；支持来源/接收时间清理及项目清空 |

## 模块与依赖

```text
安全设备 → intelligence-api → intelligence-store (intelligence.db)
                                  ↓
                           intelligence manager
                                  ↓ stable attempt ID
                   普通 EngineManager.createEngine
                                  ↓
                  指挥官 → dispatch_task → 普通 worker
                                  ↓
                   engine_done → 报告归档 → 批次结算
```

| 文件 | 职责 |
| --- | --- |
| `intelligence-types.ts` | 协议、策略、模板、批次、工程输入类型与默认值 |
| `intelligence-input.ts` | 严格字段校验、IP 规范化、稳定内容摘要序列化 |
| `intelligence-store.ts` | WAL SQLite、原子接收、去重、候选占用、快照及结算 |
| `intelligence.ts` | 与传输无关的触发、工程桥接、恢复及操作 |
| `intelligence-api.ts` | 设备鉴权、正文限制、管理鉴权与接口分发 |
| `engine-submission.ts` | 通用工程提交上下文、指挥思路快照、JSON 输入文件 |
| `ThreatIntelPage.tsx` | IP、数据源、自动分析、批次、接入文档五页签 |

复用项目注册表、SQLite 适配层、普通工程创建、指挥官、worker 及报告归档。情报模块只负责选取批次、生成工程输入和回写结果；任务数量、拆分与调度由普通指挥官按指挥思路决定。执行层不按情报来源分支，也不维护专用会话或独立报告收尾。

## 存储与接收一致性

`intelligence.db` 独立保存数据源、请求回执、事件 ID 摘要、告警元数据、IP 水位、项目策略、批次及执行尝试。工程指挥思路由现有 `doctrines.ts` 统一管理，不维护第二套模板库。策略引用指挥思路 ID，创建批次时解析最新内容；找不到时暂停创建，不改变已有批次快照。原始告警使用递增接收序号，IP 主键为 `(project_id, normalized_ip)`。

Token 只保存 SHA-256 摘要，创建或轮换时返回一次。设备 Token 只绑定一个项目和数据源。接收接口位于浏览器入口验证之前，仅该精确路径使用 Token；所有管理路径仍经过浏览器入口、登录和授权声明。读完正文后重新核验凭据，避免读取期间轮换 Token 仍能写入。

先完整解析所有记录，再在 `BEGIN IMMEDIATE` 事务内保存事件、IP 汇总及回执。请求/事件 ID 在数据源内唯一，以排序后的规范化 JSON 计算摘要。相同内容重放不增加计数，不同内容返回 409 并整批回滚。只允许协议定义的五个事件字段，不接受 evidence、客户请求、攻击载荷、目标地址或其他扩展字段。正文、请求速率与同时推送数均有上限。编号和类别不得包含业务内容。

## 触发、快照与冷却

候选满足 `未覆盖的新告警 + 冷却已过 + 无批次占用`。在同一写事务内读取并发容量、按最早新告警选取、创建批次和尝试、冻结快照、占用 IP、设置冷却截止，防止重复领取。

例如阈值 20、每批 50、并行 2：积压 120 个候选时先建两批各 50 个，余下 20 个等待容量。未到阈值的尾批不会自动凑批。

每 IP 冻结 `throughSeq`。成功仅覆盖该水位以内的告警，工程期间新告警不被覆盖。没有新告警的旧 IP 不会因冷却到期自动重复触发。

批次快照每 IP 保存最近 10 条未覆盖告警的元数据及告警计数，仅保留在 `intelligence.db` 供平台管理与结算。提交普通工程时明确提取 IP，项目目录下 `.sentinel/engine-inputs/<engineId>/input.json` 仅包含 `{"ips":["1.1.1.1"]}`。指挥官获得宿主机与容器路径，worker 获得容器路径。设备信息、来源名称、事件编号、时间、类别、级别、计数、水位和告警记录均不进入工程输入或批次提示词；手动重试同样只导出 IP。

调度在接收、策略修改和批次操作后核对，并每 5 秒补偿检查，包括冷却到期和工程完成。每轮每项目最多领取 8 批。项目并发上限与现有全局 worker 上限分别生效。

## 工程创建与恢复

两个 SQLite 库不能跨库原子提交。例如工程已保存但批次引用未写回时进程退出，重启不能再创建第二个工程。

情报库先保存执行尝试 UUID；调用普通 `createEngine(project, input, submission)`，其中 submission 保存来源、唯一键、指挥思路快照和输入。工程库 `engine_submissions(source, submission_key)` 建唯一约束，情报来源为 `intelligence`、唯一键为尝试 ID。工程行、提交关联与冻结输入在同一事务保存，任务由指挥官正常派发；即使创建调用在提交后抛错，也按尝试 ID 恢复原关联。

普通创建入口执行环境检查，失败时暂停工程。启动指挥官期间批次保持关联，接收请求、其他批次与暂停/中止操作不等待模型首轮结束。同一尝试在创建中不会重复提交，晚到的启动结果不能覆盖操作员的中止状态。

启动及定期核对所有未结束批次，不依赖 WebSocket 通知。工程重启沿用原系统的暂停策略，须人工恢复模型执行。已知工程被删除时标记失败待重试；工程库保留尝试关联作为删除凭据，防止重新创建同一尝试。

回写校验最新尝试 ID，已结算尝试不可重复结算，旧尝试不能覆盖手动重试的新状态。

## 工程执行

每批是普通工程：指挥官使用所选指挥思路的冻结内容和批次输入，通过 `dispatch_task` 派发任务，执行 Agent 经现有 `acquireTaskSession` 获取项目工具、技能、预设与权限。`bash`、资产测绘等工具遵循普通项目配置，不设置情报专用工具白名单。任务会话保存在项目普通会话目录，可查看、续跑、暂停和恢复；支持指挥官对话及普通工程操作。

分析范围为列表中 IP 的只读溯源、公开情报查询、已有资产测绘、跨 IP 关联和防御建议，不进行攻击或自动下发处置，不将上报设备作为目标。旧专用执行方式创建的失败批次应手动重试，以新工程使用普通会话执行。

报告应标明公开查询来源、查询时间、依据和局限，区分事实与推断，缺少信息时如实说明，不编造告警或攻击过程。手动重试新建尝试，从原批次快照中只提取 IP 作为工程输入。

## 状态与完成

```text
queued → creating → running ⇄ paused
                       ↓
           succeeded / failed / aborted
                         ↓
                  手动 retry → 新 attempt
                  或 discard → 放弃快照
```

worker 通过普通 `goal_complete` 提交任务结果，指挥官收到摘要后继续编排或用 `engine_done` 提交总报告；报告按普通工程流程归档。批次检查 completed、非空报告及成功任务对全部批次 IP 的覆盖；target 为空的成功任务视为覆盖整批，按 IP 派发时每个 IP 都须有成功任务。已失败但被同目标成功任务补足的派发不阻止整批成功，未覆盖目标不能标记已处理。

失败或中止释放运行容量但保留 IP 占用；不自动重复消耗模型额度。重试受当前项目并发限制，不修改冷却起点或原输入，旧工程保留。放弃覆盖原快照水位并释放 IP，后续新告警仍可在冷却后触发。暂停占容量且不会标为已处理。

## 清理与扩展

按来源/接收时间清理前先预览，并阻止清理关联未结束或待重试批次的记录。列表从剩余事件计算计数、来源与时间。水位和幂等摘要保留，重放不会重新制造旧任务。

清空项目情报删除告警、IP 与批次，但保留数据源、策略及幂等摘要，工程指挥思路独立管理。已建工程、输入 JSON、报告与普通任务会话独立保留；清空情报不等于删除工程中的副本。删除项目清除相应情报及凭据。

后续增加 RSS、域名或 URL：新增接入适配器与规范化能力，复用存储与桥接接口。其他任务可复用模板快照、稳定尝试关联和整批回写；候选选择由其业务模块负责，首版不提前设计通用编排系统。

隐私边界：平台新接收及存储只包含威胁来源 IP、事件编号、发生时间、类别与级别，另由平台生成来源、接收时间、序号和计数；自动提交给指挥官和执行 Agent 的业务数据只有 IP 列表。移除 evidence 是协议收紧；旧客户端需更新。已有数据库、工程输入、会话与报告不自动删除，历史副本需单独清理。普通工程仍沿用项目工具和文件访问权限，此处限制的是自动提交数据，并非新增文件访问隔离。
