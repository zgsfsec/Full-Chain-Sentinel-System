# 模型自定义请求头

模型库支持给单个模型配置额外的 HTTP 请求头。请求头会随该模型发出的 API 请求发送，适用于服务商或中转站要求的自定义鉴权、来源标识和网关选项。

## 配置

打开「设置 → 模型」，编辑模型，在「连接配置」页添加请求头名称和值，再保存。配置写入本机 `<配置目录>/agent/models.json` 的该模型 `headers` 字段；文件权限为 `0600`。请求头值可能包含密钥，因此控制台只读取并显示名称，不会把已保存的值发回浏览器。编辑时留空表示保留原值，删除整行表示移除该请求头；修改已保存请求头的名称时，需要重新填写它的值。

请求头按模型单独配置，不会自动作用于同一渠道的其他模型。已有 API Key 仍由 Pi 的认证流程处理；只有端点明确要求使用非标准名称时，才需要额外配置鉴权头。

## 常见示例

| 请求头 | 常见用途 | 示例或注意事项 |
| --- | --- | --- |
| `Authorization` | Bearer 鉴权 | Pi 通常会根据「API Key」自动生成。只有端点要求不同的 Authorization 格式时才手动设置。 |
| `api-key` | Azure OpenAI 或兼容网关鉴权 | 只在端点文档要求 `api-key` 头时填写；不要把同一个 Key 同时放进多个鉴权头。 |
| `X-API-Key` | 部分自建网关鉴权 | 这是服务商约定，不是统一标准；名称和值按网关文档填写。 |
| `anthropic-version` | Anthropic API 版本 | Anthropic 消息协议通常自动发送；自定义兼容网关要求时再配置，例如 `2023-06-01`。 |
| `anthropic-beta` | Anthropic Beta 能力 | 仅在使用对应 Beta 功能且端点要求时填写；值可能随服务商更新。 |
| `HTTP-Referer` | OpenRouter 来源标识 | 部分接入会要求；Pi 已提供默认来源头，需要时可在模型级覆盖。 |
| `X-Title` | OpenRouter 应用名称 | 部分接入会要求；Pi 已提供默认值，需要时可覆盖。 |
| `X-Enable-Thinking` | 中转站自定义思考开关 | 例如 `false`，仅当中转站文档明确说明会把它映射到模型参数时才有效。 |

上表只是常见模式，不代表每个端点都接受这些头。实际名称、大小写与值都以服务商文档为准。HTTP 请求头名称不区分大小写，但网关可能对取值有自己的要求。Pi 通常会自动填写 `Content-Type` 等协议头，不建议重复配置。

## 关闭思考的限制

目前没有跨服务商通用的「关闭思考」请求头。多数 API 将此选项定义为 JSON 请求体字段，例如 `enable_thinking: false`；Pi 会根据模型协议与能力配置生成相应请求体。自定义请求头只有在你的中转站明确实现了类似 `X-Enable-Thinking: false` 到请求体字段的映射时才有用。没有该映射时，添加这个头不会关闭模型思考。

配置思考协议时，优先使用模型能力中的兼容协议选项和「关闭推理」能力映射；只有端点明确支持自定义头转发或转换时，才使用自定义请求头。

## 安全与排错

- 不要把 API Key、Cookie 或其他凭据粘贴到截图、诊断文本或公开工单。
- 请求头值保存在本机明文 `models.json`，请保护配置目录备份；权限设置为 `0600`。
- 浏览器只收到请求头名称，不会收到已保存的值。删除请求头行并保存后，对应配置才会移除。
- 若请求返回 `401` 或 `403`，核对鉴权头名称、值，以及 API Key 是否已由 Pi 自动发送。
- 若请求成功但功能没有生效，确认服务商是否支持该头、是否要求精确值，以及是否会将头转换为请求体参数。
- 自定义请求头不能改变服务商未公开支持的行为，也不会绕过模型端点自身的限制。
