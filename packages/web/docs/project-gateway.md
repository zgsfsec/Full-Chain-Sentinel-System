# 项目网关

新项目创建两个容器：工作容器执行工具，常驻网关持有网络命名空间。直连、SOCKS5/HTTP、订阅、WireGuard 和 OpenVPN 都通过该网关。切换出口只替换网关里的客户端，不重建两个容器，工作容器里的安装包、文件和后台进程保留；已有网络连接可能中断。

切换前校验配置并短暂暂停工作进程，待新客户端就绪后恢复。客户端启动失败时恢复原配置；恢复也失败时阻断出口并报错。客户端异常退出后网关会阻断出口，修正配置后重新保存或启动项目恢复。隧道就绪不代表远端一定可达，仍应使用代理页的连通性测试确认。

项目代理保存、档案修改、订阅刷新和默认代理更改都会应用到运行中的网关。手动停止的项目保持停止，下次启动时应用。

已有项目保留原容器结构。只有操作员显式选择“重建容器”才迁移；重建会删除工作容器可写层，先备份 `/work` 之外需要保留的文件。旧项目直连的 host/bridge 选择仍保留，新网关使用 Docker 隔离网络。访问宿主机使用 `host.docker.internal`，容器里的监听端口不会自动对外发布。

网关默认使用 `sentinel:latest`，需要 `iproute2`、`iptables`（含 IPv6 命令）、`curl`、`timeout`，隧道还需要 `wireguard-tools` / `openvpn`。仓库 Dockerfile 已包含这些组件；较旧的本地工具镜像可能需要更新。可通过 `SENTINEL_GATEWAY_IMAGE` 指定包含这些组件的独立网关镜像，不影响工作容器镜像。sing-box 程序从设置中选择的 sing-box 镜像提取，镜像 ID 更改后重新提取。

内核不提供 IPv6，或网关内所有接口及新接口默认配置均禁用 IPv6 时，网关仅保存、恢复和保护 IPv4 网络，不要求 IPv6 防火墙工具。IPv6 可用时仍必须完成 IPv6 路由和防火墙初始化；权限不足或防火墙故障不会被当作“IPv6 已禁用”跳过。环境复检会在无外网连接、无宿主目录挂载的一次性容器内执行真实网关初始化。初始化失败会显示失败步骤和底层错误，不再统一归因为工具缺失。

网关配置保存在 `<配置目录>/gateways/<项目 ID>/`，仅挂载到网关，工作容器只挂载可更新的 DNS 文件。订阅和代理凭据不应进入 Git 或诊断日志。

订阅默认以 `clash.meta` 获取，保留供应商提供的 TLS 参数；自定义 User-Agent 保留。更新后需要刷新一次订阅才能替换旧缓存。第三方 FOFA BaseURL 支持域名、反代前缀和 `/api/v1` 根路径；未提供账户接口（404/405/501）的渠道改用最多一条结果的搜索验证，可能消耗渠道查询额度，认证失败仍拒绝启用。
