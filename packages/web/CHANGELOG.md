# Changelog

## [Unreleased]

### Breaking Changes

- 插件安装改为本地构建：`plugin.json` 不再接受 `image`，改用 `build.dockerfile` / `build.context`；安装请求带上插件包，host 解压后执行 `docker build`。旧插件需要补 Dockerfile 并删除 `image`。

### Breaking Changes

- The console has no default directory any more: without a project there is no container, so the chat is replaced by a full-screen project-required screen with inline project creation and the project list
- Removed the host-session fallback and the `SENTINEL_ALLOW_HOST_SESSIONS` escape hatch, the "back to default directory" picker entry, and `switch_project: null`. Bash, the file tools, and the file panel all require the project container
- 产品改名：ZGAgent →「全链哨兵 Full Chain Sentinel System」，标识符统一为 `sentinel`。数据目录 `~/.zgagent` 首次启动自动迁移到 `~/.sentinel`（在 `config.ts` 里做，迁移失败会打印手动命令而不是静默当新装）；环境变量 `ZGAGENT_CODING_AGENT_DIR` / `ZGAGENT_CODING_AGENT_SESSION_DIR` / `ZG_PROJECTS_DIR` / `ZG_GATE_TOKEN` 等改为 `SENTINEL_*`；镜像改为 `sentinel:latest`、容器名前缀 `sentinel-`、命令改为 `sentinel-web`、包名改为 `@earendil-works/sentinel-web`；登录与网关 Cookie 改为 `sentinel-auth` / `sentinel-gate`；预设导出标识改为 `sentinel-presets`；DroidBridge APK 包名改为 `com.sentinel.droidbridge`（手机上需重新安装）。会话文件里的自定义条目类型（`zg-mode` / `zg-preset` / `zg-status` / `zg-goal` / `zg-loop-guard`）与 models.json 里的历史槽位 id（`zg-endpoint` / `zg-commander` / `zg-judge`）**故意保留原名**：它们是已有会话与模型配置里的键，跟着改会让那些文件读不出来

### Changed

- 代理编辑器改为宽版左右分栏：左侧是 SOCKS5/HTTP、订阅、WireGuard、OpenVPN 四种出口类型，右侧只显示当前类型的说明与表单；隧道配置框不再把弹窗撑出屏幕，窄屏自动折叠为上下布局。表单字体与全站对齐：标签和普通输入框用 13px 无衬线，配置框用 12.5px 等宽，不再整块都是小号等宽字。
- Windows 控制台只发布一个资产：删掉裸的 `sentinel-web-windows-x64.exe`，只留 `sentinel-web-windows-x64.zip`（exe + 容器用的 `replayd/`），与另外四个平台「一个平台一个归档」对齐。裸 exe 就是 zip 里那个可执行文件，唯一多给的只是省一次解压，代价是发布页多一个看名字看不出差别、下载后要到第一次「发包」才发现缺二进制的资产；而 release 正文由 `--generate-notes` 生成，从不解释这两个资产怎么选。构建脚本本地仍产出 exe（它是 zip 的内容，也是 workflow 里 `--version` 冒烟测试跑的那个），只是不再单独上传。
- 工程列表去掉「目标 / 任务」列，新建工程向导不再显示按输入行数识别的目标数量；目标清单仍按原文交给指挥官，避免用户输入的长任务被误算成目标条数。
- 指挥端点改为普通模型角色，与主模型、守门模型、漏洞评审、监督模型同排，点击「更换」直接从模型库选择已有模型或跟随主模型；不再单独维护 Base URL 和 API Key，旧的指挥端点会迁移为模型库条目。
- 新建工程改为三步向导：目标 → 指挥 → 执行。每步独立校验，左侧步骤轨可回看已完成步骤；定时计划、执行上限和命令守门集中在最后一步确认，提交前再统一校验一次。
- 设置 → 通知改为双卡工作台：钉钉和飞书并排，各自有启用开关、连接状态和测试按钮；推送内容与正文字数上限放在下方的共享卡片，窄屏自动单列。
- 运行中也能切换项目：侧栏项目选择器不再因当前会话正在运行而被禁用。切换只改变控制台的项目上下文（会话列表、文件、容器与快照），原会话连同它的工具、容器与目标循环在后台继续运行，切回项目后仍可在会话列表里打开继续看；后台会话的运行报告、通知和审批不受影响。
- 删除项目改为两个明确选项，且都需要输入完整项目名确认：「仅删除容器」与「删除项目数据」。确认从表格行内（以及侧栏下拉里）的紧凑表单改为居中的窄弹窗：标题带项目名、一行元信息（容器与记录数）、一段说明写清两个范围的后果，输入完整项目名后两个动作才可用；两个范围本身就是底部两个按钮（危险动作为实心红），没有单选也没有中间卡片。「停止容器」与「重建容器」也改用同一个弹窗，正文只有一段说明。
- 项目页改版：表格列瘦身为「项目（名字 + 状态点 + 容器短名）/ 会话 / 漏洞 / 操作」，行内只留一个主动作与「⋯」菜单（停止容器 / 重建容器 / 删除项目…），当前项目显示「当前项目」并带左侧蓝条；未运行的项目主动作变成「启动容器」。会话数改为服务端按项目统计会话文件数，每个项目都有真实数字（此前只有当前项目可知，其他行全是「—」）。

- 留证截图可以走自定义 SOCKS5 出口：`replay_capture` 新增 `proxy` 参数（`socks5://[user:password@]host:port`），只作用于这一次发送——不是系统代理，也不改容器网络。代理会被填进 replayd Repeater 页的「上游代理」框并随发送交给引擎，所以截图里就能看到出口；域名交给代理解析（远程 DNS），目标站只有经代理可达时也打得通。地址是容器视角：host 网络下 127.0.0.1 是宿主机，bridge 下用 `host.docker.internal`。代理连不上/认证失败报 `upstream_connect`/`upstream_auth` 并带排查提示，不会误报成「目标拒绝连接」；非 socks5 协议在启动 replayd 和问审批之前就被拒绝。
- 对话页工具栏新增「终端」：在项目容器里开一个真正的 pty，能跑 `top`、`nc`、`ssh -t` 这类需要终端的交互式命令。pty 由容器内的 util-linux `script` 创建（`docker exec -i … script -qfc 'stty rows R cols C; exec bash'`），宿主机侧不需要 node-pty 之类的原生模块，控制台照旧是单文件二进制。它不过审批、不进会话记录——它就是操作员自己的 shell；关掉面板后里面的进程继续跑（盯监听器是主要用途），重开时回放 256KB 滚动缓冲。同一时刻只有一个终端，终端属于某个容器：换项目后打开会提示「上一个终端还在项目 X 里」，由操作员决定结束它还是保持不动。已知限制：pty 尺寸在打开时固定（`script` 无法中途 resize，全屏程序要退出重进才对齐），工具镜像里没有 `vim`/`less`。
- 自定义代理（侧栏「代理」页 + 项目页与侧栏项目选择器里的项目代理）：让项目容器的出站流量走自己的代理。代理是**命名档案**——在「代理」页增删改查，每个档案二选一地描述出口：**SOCKS5 / HTTP 地址**（类型、地址、端口、可选账号密码，HTTP 可开 HTTPS 上游），或**订阅链接**（贴机场/自建面板的地址，保存时拉取一次，解析出多个节点后选一个）。订阅支持四种响应形态：base64 分享链接、明文链接列表、Clash YAML 与 sing-box JSON；分享链接覆盖 `ss://`（SIP002 与老式整串两种拼法、`?plugin=`）、`vmess://`（v2rayN 缩写字段）、`vless://`（含 reality 的 `pbk`/`sid`/`fp`）、`trojan://`、`hysteria2://`/`hy2://`、`tuic://`、`socks5://`、`http(s)://`，`ssr://` 与不认识的协议**跳过并说明原因**而不是整份失败。**节点缓存进档案**（`proxies.json`），绝不在起容器时联网：断网机器照样能启动项目，机场掉线也不会让已经在跑的项目连不上——刷新失败只记错误、保留上一次的节点。生成的配置里**所有节点都在，路由走一个 `selector` 出站**，`selector` 前面还有一个 **`urltest` 的 `auto` 组**（每 3 分钟按测速地址给节点排序），所以「自动择优」只是列表里的一个选项而不是另一种模式。**切换节点不需要重建容器**：项目侧换节点走 sidecar 的 Clash API（`PUT /proxies/proxy`），配置里为此生成 `experimental.clash_api`（每项目随机 secret，端口由 Docker 在 `127.0.0.1` 上临时分配，切换时才用 `docker port` 问一次），实测容器 id 不变、流量当场改道、已建立的连接不迁移；没有运行中的 sidecar 时只记录选择、下次启动生效。这个管理面开在 sidecar 的 netns 里，作业容器共享同一命名空间，所以**必须**带 secret（无 secret 401），secret 只存在于生成给 sidecar 的配置里（0600、只挂 sidecar）。保存与刷新后都会跑 `sing-box check`。**默认代理与 sidecar 镜像**（默认 `ghcr.io/sagernet/sing-box:v1.13.15`，可换镜像源并一键拉取）与**容器网络**合成**设置 → 环境 →「容器网络与代理」一张卡、一个「保存」**：容器要么走宿主机网络要么挂 sidecar，挂哪个 sidecar、用哪个镜像本来就是同一个决定，分成两张卡要保存两次；这两项作用于整个控制台而不是某个档案，「代理」页只留档案本身。**WireGuard 档案**（第三种出口类型）：一条隧道而不是一个代理。**配置直接粘贴 `wg0.conf`**——机场和自建面板给的就是这个文件，所以不让人填十个字段；粘贴后只做两件事：把 `DNS =` 那行剥出来（`wg-quick` 会拿它去调 `resolvconf`，镜像里没有）改用挂进作业容器的一份 `/etc/resolv.conf` 传进去，以及去掉 `SaveConfig`（文件是只读挂载）。其余行原样保留，包括 `PostUp` 与多个 `[Peer]`。它的 sidecar **不跑 sing-box**，而是用 `wg-quick` 在共享命名空间里建真实的 `wg0` 网卡与默认路由——因为 sing-box 的出站只能拨 TCP/UDP，**ICMP 根本没有入口**（实测 ping 100% 丢包），要"连 ping 都走隧道"就必须是真接口。实测：粘贴带 `DNS =` 与 `SaveConfig = true` 的配置，写入时两者都被剥掉，握手成功后 `ping 对端` 与 `ping 8.8.8.8` 均 0% 丢包。另有一个 **kill-switch 开关（默认开）**：隧道起来后删掉直连的默认路由，隧道掉了不会漏回宿主机网络。sidecar 用**工具镜像**（`sentinel:latest`，已加入 `wireguard-tools` / `iproute2` / `iptables`），不需要第二个镜像，但**必须重建一次工具镜像**才能用；它额外需要 `--cap-add NET_ADMIN` 与 `--sysctl net.ipv4.conf.all.src_valid_mark=1`（wg-quick 的 kill-switch 要设这个 sysctl，而容器里 `/proc/sys` 默认只读）。隧道没有节点概念，所以没有 selector、没有自动择优、也不能运行时切节点。
- **OpenVPN 档案**（第四种出口类型）：第二条隧道，与 WireGuard 档案同形（真网卡 + 真默认路由、kill-switch 默认开、没有节点也没有运行时切换），区别是客户端为前台运行的 `openvpn` 进程，所以 **sidecar 的主进程就是隧道本身**。**粘贴内联证书的 `.ovpn`**，账号密码**单独填**（写进 `<配置目录>/proxy/<id>.ovpn.auth`，0600，只挂 sidecar，不进粘贴的文本），DNS 可留空——服务器 push 的解析器由 sidecar 的 `--route-up` hook 写到挂载文件里，控制台读回来生成作业容器的 `resolv.conf`。粘贴的配置会剥掉 `daemon`（必须前台，否则 sidecar 退出会带走作业容器的 netns）、`log` / `log-append` / `status`（日志要留在 `docker logs`，就绪与失败判定都读它）、`auth-user-pass`（改用挂载的凭据文件）与 `up` / `down` / `route-up` / `tls-verify` 等脚本钩子（sidecar 为自己的 hook 必须开 `--script-security 2`，留着等于让粘贴的文件执行任意命令）；`ca ca.crt` 这类外部文件引用被拒绝并说明改法，`dev tap*` 与 `static-challenge` 同样明确报错。**就绪判定三种信号一起用**：容器状态、日志里的致命行、以及 `docker exec <sidecar> ip -o addr show` 是否真有 tun 设备——因为连不上时 openvpn 会一直重试而容器始终 `running`（实测不可达的 remote 4 分钟重试 22 次），只轮询日志会永久挂住；60 秒等不到就把最后一行有意义的日志（`RESOLVE:`、`TLS Error:`、`AUTH_FAILED` 等）当错误抛给操作员，避免「容器在跑但没走隧道」的静默泄漏。kill-switch 在 `--route-up` 里删掉直连默认路由，实测断线时路由全消失、`ping` 报 Network is unreachable（失败即断网，不漏流量）。**同一份证书同时只能有一个连接**：服务器未开 `duplicate-cn` 时多个项目共用一份档案会互相踢下线（实测 60 秒一次 `ping-restart`、丢包 0% → 50%/100%），代理页因此在隧道档案被两个以上项目使用时打「证书共用」警告（只警告不禁止，服务器配置控制台问不到）。工具镜像加入 `openvpn` 与 `iputils-ping`，与 WireGuard 一样**必须先重建一次工具镜像**。真实服务端端到端验证：sidecar 1.5~1.8 秒到 `Initialization Sequence Completed`，作业容器里 `ping` 隧道对端 0% 丢包、读不到 `/etc/openvpn/client`（只共享 netns）、服务器推送的 8.8.8.8 被写进作业容器的 `resolv.conf` 并生效。
**项目只记住档案 id**，外加**可选的一个节点**：跟随默认 / 不使用 / 指定某个档案，选了订阅档案还能**只给这个项目钉住其中一个节点**（同一个订阅常被多个项目共用，但各自应该从不同出口走），所以改一次档案、用到它的项目下次重建容器就生效；钉住的节点被刷新掉时回落到档案自己的选择而不是让配置生成失败；删除档案时用它的项目回到「跟随默认」。新建项目可以在创建表单里直接选档案与节点，侧栏项目选择器的每一行也能就地展开档案与节点。**控制台拥有 tun 入口、DNS 逃逸与路由顺序**：容器内解析走 Docker 内嵌 DNS（sidecar 挂在自建的 user-defined 网络上，`127.0.0.11` 就在同一个 netns 里，解析不必穿过隧道），`protocol: dns` 与 `ip_is_private` 直连、其余走代理。**节点凭据不进作业容器**：生成的 `config.json` 只挂进 sidecar（`:ro`），Agent 在 Kali 容器里读不到它；代价是目标连不回容器里的监听（要反弹 shell 就把该项目设成「不使用代理」）。**sidecar 与容器是成对的**：创建时先起 sidecar 再起容器，停止时反过来；Docker 不允许挂到一个没运行的 netns 上，而**重启 sidecar 会让已在运行的容器网络静默失效**（容器仍是 `Up`，但 `/sys/class/net` 里连 eth0 都没了），因此环境页用「network mode 指向的容器 id」与「sidecar 启动时间晚于容器」两条判据识别这种失效，并在下一次使用该项目时重建容器（`/work` 不受影响）；只改了档案而容器还活着时只报告不重建。`--add-host` 不能与 container 网络模式共用，所以 `host.docker.internal` 由 Docker 内嵌 DNS 解析（Docker Desktop），Linux 上由控制台在每次启动后补写 `/etc/hosts`。档案存在 `<配置目录>/proxies.json`（0600，含账号密码与订阅 token），生成的配置按项目 id 存在 `<配置目录>/proxy/<id>.json`，删项目时一并删除。

- DroidBridge 的守护进程（APK `versionCode` 3 / `versionName` 0.1.2）：反连服务在主进程，守护进程跑在 `<包名>:guard` 独立进程，每 15s 给主进程发一个 SIGCONT。模拟器与部分系统的节能策略会给 app 进程发 SIGSTOP——所有线程停住、TCP 仍是 ESTABLISHED，控制台只看到一个「在线但什么都不回」的设备，而冻住的进程自己救不了自己（SIGCONT 必须由外部发）。第二个进程是唯一不需要 root、不需要 adb 的「外部」：同 uid，内核允许它给兄弟进程发信号（`Process.sendSignal`，公开 API），它自己带前台服务，平台也不会把它当缓存进程冻掉。信号发失败（进程已被杀）或进程表里找不到反连进程时，它重新拉起反连服务，并把次数写进通知栏。它救不了「整个包一起被冻」（那时它同样被冻住，只能靠设备外的看门狗或关掉模拟器的后台冻结）。设置页有开关（默认开，代价是第二个前台通知，渠道重要度为 MIN、默认折叠）；操作员点「停止反连」时两个进程一起停，所以它不会把主动停掉的服务又拉起来
- 主对话的文件上传：拖拽或粘贴任意文件到输入框，或点输入框上方的「附件」按钮选文件（「图片」按钮仍只收图片），每个文件一个 chip（名称、大小、上传进度、可删除），上传完不自动发送——按 Enter 才随消息发出。文件写进当前项目工作目录的 `uploads/`（重名自动加 `-2`/`-3`，绝不覆盖已有文件），发送时在消息正文前拼一段「已上传文件（可用 read/bash 直接读）：- `<绝对路径>`（大小）」的清单，模型用自己的 read/bash 去读。传输走 `POST /api/upload?name=…`（body 是原始字节，XHR 上报进度，`fetch` 没有上传进度事件），服务端边收边写盘（单文件上限 64MB，超限回 413 并删掉半成品；中断回 400 并清理；没选项目回 409），文件名净化成单段：`../../evil.sh` → `uploads/evil.sh`、`/etc/passwd` → `uploads/passwd`、`..` → `file`，并用独占创建抢名字，所以并发的同名上传不会互相覆盖。图片仍走原来的 vision 内联（粘贴截图不落盘），非图片文件才落盘给路径——模型消息只支持 text 与 image 两种 part，没有 document part，这是唯一可行的形式。宿主会话与容器会话都能用：文件写在挂载的宿主侧，容器里的 `/work/uploads/…` 与宿主绝对路径指向同一个 inode；上传后切换了项目再发送会被拦下并提示重新上传（旧项目目录没挂进容器，那个路径模型读不到）

- 审批（原「守门审计」，侧边栏改名为「审批」）拆成两个标签页：「AI 审批」是守门模型的判定流水，「自动审批」是没有人判定的调用流水——自动执行模式、审批模式的人工放行与人工拦截、以及守门没覆盖的工具（read / edit / write、MCP 开关关闭时）都会各留一条。判定入口从 bash 一个扩到全部工具：新增挂在 `pi.on("tool_call")` 上的两个扩展，`mcp__*` 调用在 AI 审批模式下送守门模型判定（与 bash 共用同一套模型和拦截回执，两个开关：默认判定 MCP、默认不纳入插件），判定失败仍放行并记「请求失败」；其余调用只写流水不拦截。每条记录带 `approval` 字段（ai / human / auto），两个标签页合起来覆盖每次调用且只记一次。审计页新增「会话」筛选下拉，表格在自动审批标签页改显示会话名
- 自定义 MCP 服务器（设置 → MCP）：在控制台里增删改查 MCP 服务器并逐个「测试连接」，不再需要手写 JSON。**配置由哨兵自己拥有**，存 `<配置目录>/mcp-servers.json`（0600），会话通过给 `createMcpExtension` 传自定义 `loadConfig` 只读这一份文件，pi 原生的 `mcp.json` 一概不读——因此列表里没有的服务器对 Agent 就不存在，手写的文件不会偷偷加进一个操作员看不见的工具。支持三种传输：`http`（远程 streamable HTTP，可配请求头）、`sse`（旧版 HTTP+SSE，服务器在首个 `endpoint` 事件里给出消息地址）与 `stdio`（`command` + 参数 + 环境变量 + 工作目录）。SSE 与 HTTP 共用 `url` / `headers`，由 pi 的 `createDefaultTransport` 按 `type` 选择传输，因此 CLI、`/mcp` 管理器与「测试连接」走的是同一条实现。**stdio 是这套容器隔离里唯一的例外**：它在控制台宿主机上直接 spawn 进程，不在 Kali 容器内、不经过 bash 审批、不进守门审计，所以 stdio 条目必须勾选「我确认该命令会在控制台宿主机上直接执行」才能保存（挂载时再校验一次，手改文件清掉该标记同样不会连接），页面上有醒目的风险提示。暴露方式可选 codemode（默认）/ tool_search / direct / hidden，另有单次请求超时；工具以 `mcp__<服务器>__<工具>` 注册，仍受「设置 → 权限」的 `mcp` 总开关约束。**测试连接**走与真实会话相同的 `McpServerConnection`（同一套 `${VAR}` / `!cmd` 解析、`~` 展开与 cwd 解析），一次连接读取工具列表后关闭，不保存、不影响运行中的会话，结果（成功 / 需要 OAuth 登录 / 失败，含 stdio 的 stderr 尾部）记在页面上；本页不做 OAuth，需要登录的服务器提示去终端跑 `sentinel mcp login`。保存与删除会重建活动会话（有会话在跑时拒绝），页面不显示会话内的实时连接状态。「设置 → 权限」的 `mcp` 总开关下逐个列出这些服务器，每行一个开关：它写的就是本页的「启用」，两个页面是同一个开关的两个视图，因此不会互相矛盾；协议只传 `enabled` 一个字段，避免把某个页面里陈旧的 URL / token 覆盖回文件

### Changed

- 项目容器的默认网络从 Docker 的 bridge 改为 host，并且 host 模式下不再授予 `NET_ADMIN`：bridge 下容器里的监听端口谁也连不回来、ARP/广播/VPN 网段都看不见，host 模式才是渗透工具需要的网络位置；代价是与宿主机抢端口（控制台的 7777、DroidBridge 网关的 9944）且不再有网络隔离。`NET_ADMIN` 在 host 命名空间里等于能改宿主机的网卡、路由与 iptables，所以只在 bridge 模式下保留；`NET_RAW` 两种模式都保留（扫描器要的原始套接字）
- 控制台默认监听地址从 `127.0.0.1` 改为 `0.0.0.0`：服务器上 `npm --prefix packages/web run start` 起来即可从外部访问，不必再传 `--host`；启动日志会列出各网卡的局域网地址（都带入口串）。只想本机访问仍可传 `--host 127.0.0.1`。库调用 `startSentinelServer` 的默认值不变（仍是回环），只有命令行入口改成通配绑定
- DroidBridge APK 的 `versionCode` 提到 2、`versionName` 从 `0.1.0` 提到 `0.1.1`：此前每次构建的版本号都一样，装到手机上后从外面完全分辨不出装的是哪一次构建（本轮排查「重装过了但拉大文件仍然把 app 打挂」时就卡在这里——无法确认手机上跑的是不是带流式拉取的那一版）。现在用 `dumpsys package com.sentinel.droidbridge | grep versionName` 或系统「应用信息」页即可确认，构建脚本产出的 APK 也附上 sha256 供传输后核对
- 漏洞评审改成「模型只判断 CVSS 3.1 八项指标，分数与等级由代码算出」：原来一次要模型给 `severity` + `cvss` + `cvss_vector` 三样，它能给出互相矛盾的三份答案（中枢的「等级与分数不一致」警告就是为这种情况准备的），现在模型输出 `av/ac/pr/ui/s/c/i/a` 八个指标，`cvss.ts` 按官方公式算基础分（含规范的 Roundup 取整与 PR 随影响范围加权的规则）并由分数定五级，等级与分数永远一致——11 个公开向量（含 Log4Shell 10.0、反射型 XSS 6.1、本地提权 7.8）全部逐位命中。另外评审提示词不再把「提交者自评」喂给模型：那等于把要校验的答案先递给它，模型照抄自评时校准看起来什么都没改；现在它只凭证据独立判断指标，自评仍留在记录里。提交侧也加了一条提示词：自评只是初值、中枢会用 CVSS 3.1 指标重算，按证据老实评级而不是伸手拿最高档
- 重新评审失败不再擦掉原判：重新排队时保留上一次的 `severity` / `reason`，失败后这些字段仍可读，只有新判决落地才会整体覆盖
- POC 库的两个 Agent 工具补上「通用指纹」定位说明：模板只描述某个产品/CVE 的通用特征，不是针对当前目标的现成攻击脚本，而模板里的 `path` / URL 前缀只是作者按常见部署写的一种猜测（`/api`、`/api/v1`、反代前缀、自定义目录各不相同）。新增两条提示词规则——先按侦察结果确认真实前缀再把匹配逻辑搬过去，别照抄路径直接打；照抄路径跑一次的未命中不构成「目标不受影响」的证据。另外每次 `poc_read` 返回都会在模板全文之后附一句同样的提醒，且刻意放在输出截断之外，模板再长也不会把提醒截掉
- POC 库在 30 万条模板下的查询与导入路径：列表查询从 `SELECT *` 改成只取摘要字段（模板正文不再被读出来又丢弃），并补上 `(imported_at DESC, id)` 与 `(severity, imported_at DESC, id)` 两个列表索引——此前无索引的 `ORDER BY imported_at` 让每次翻页都全表扫描并排序，30 万条实测单次 257ms（按等级筛选 114ms、标签 241ms），而且 node:sqlite 是同步调用、这段时间整个控制台卡住；实测同一库首页列表与等级/标签筛选都降到 1ms（关键字搜索仍是 `%词%` 全表扫，约 270ms 未变）。索引写在 schema 里，每次打开都会补齐，已有的 pocs.db 下次启动自动加上。导入改成流式读取 zip（逐条解压-解析-入库，不再把整个压缩包的所有模板先读进内存）并按每 5000 条提交一次事务：30 万条整库导入从逐条 autocommit 的约 2.9 分钟降到 8.7 秒，同时回滚日志不会涨到写入量那么大、也不会因为一个意外错误丢掉整批

- The vulnerability reviewer's ratings drifted high, and the cause was the prompt rather than the model: it listed the eight CVSS metrics without a single criterion for judging them, so the reviewer fell back on a worst case. It read 「普通用户即可触发」 as "no privileges required" (PR:N instead of PR:L) and pulled the three impact axes up together, so a read-only order-IDOR came back as 9.8. The reviewer now gets a rubric — what each metric means, that PR follows from the credentials in hand rather than from how dangerous the flaw is, that a read-only finding leaves I and A at N, that UI:R has to drag the impact down with it, that fingerprint information (version banners, stack traces) is not a confidentiality impact, that XSS costs at least C:L — and the instruction 「不要照抄提交者的乐观假设」, which literally told the model to discard the submitter's *cautious* framing and escalate, is gone. A finding the evidence does not support is now **capped at the medium bucket**: the impact axes give way until the score fits and the vector is rewritten to match, so the number and the vector still describe the same finding, and the timeline says the number was lowered and why. A level no reviewer ruled on — the review failed, or has not come back — is labelled 「自评」 in the console and 「代理自评（未评审）」 in the exported report instead of standing as a bare number, and the agent's own claim is kept beside the reviewer's verdict. On five benchmark findings with known correct ratings, the average deviation went from 3.7 to 0.02 CVSS points

- A reviewer reply that did not use the spec's exact letters lost the whole review: the parser wanted eight two-letter values and anything else was an error, so a verdict that said `"av":"Network"`, or answered with a CVSS vector string, or nested the metrics one level down, was thrown away — and the record then kept the agent's own rating as if it had been checked. The parser now also accepts the spec's words per metric (「Network」, 「Low」, 「Unchanged」…), a vector string, and a `metrics` object, while a value that is neither the letter nor the word still fails loudly

- 漏洞评审的分数仍然偏高，这次查出的根因不是「整体偏高」，而是**三根轴各自被滥用**：可用性影响 `A:H` 挂到了弱口令、硬编码 API Key、HTTP 明文这类根本不会让服务不可用的记录上；完整性影响 `I:H` 挂到了只读类（源码泄露、只读 SQL 注入）；影响范围 `S:C` 挂到了同一应用内的跨租户读取。提示词里这三条规则早就写了，评审模型在生产语料上仍是照着「这听起来很严重」把三根轴一起拉满——软约束不生效，所以改成硬约束：评审先回答四个**能力问题**（read 拿到什么/破坏了哪层保护、write 能不能改数据或接管账号、down 能不能让服务不可用、cross 会不会跨到别的安全域），C/I/A/S 再由这四个答案推出来，程序侧按能力把模型自相矛盾的那几根轴**收回来**（`applyCapabilityLimits`，只降不升），降过的记录在时间线里写明降的是哪几根轴与最终分数。另外把「证据不足」和「没有影响」分开：只有配置声明、只有权限声明而没有实际利用结果的判存疑，而不是给一个 0.0 分；弱加密、缺安全响应头、验证码可绕过、用户名枚举这类「保护被破坏」算部分机密性影响，不是没有影响。生产 270 条重评实测：严重 108 → 93，`S:C` 58 → 30、`I:H` 136 → 122、`A:H` 76 → 72，整体净下调 0.43 分；真 RCE 仍是 10.0，认证绕过统一落在 9.1，只读类落到 4.3–7.5

### Fixed

- DroidBridge APK 的 CI 构建不再依赖阿里云 `gradle-plugin` 镜像：该镜像对 `com.android.tools.build:gradle-settings-api:8.5.2` 返回 502 时，Gradle 不会把它当 404 继续尝试 `google()`，整次发布直接失败。CI 现在使用官方 `google()` / `mavenCentral()`；本地构建仍默认走镜像，镜像故障时可用 `SENTINEL_GRADLE_MIRROR=off` 切回官方仓库。
- 项目页的「停止容器」「重建容器」「删除项目…」恢复可用：这三项此前只把状态写进页面，对应的确认弹窗根本没渲染，点了没有任何反应（看起来像摆设）。同时把四个并列的 `pending*` 状态合并成一个 `{action, id}`，让「菜单项没有对应弹窗」变成类型错误而不是静默失效；`.data-table` 的 `overflow: hidden` 也去掉了——行内 `⋯` 菜单是绝对定位的，被表格裁掉后最后一行整菜单都看不见，圆角改由首尾行自己承担。

- iOS 真机验收修复：Frida 17 移除 `Module.findExportByName`/`Process.exit`，内建脚本改用兼容 helper 与 C `exit()`；Mach-O 解析按实际小端读取（TS 与 Swift），`app_info` 不再把 arm64 报成未知架构；daemon `posix_spawn` 关闭子进程继承的管道写端，后台 tcpdump 不再让 `ios_shell`/`ios_capture_start` 等到超时；抓包改用 pidfile，不再依赖设备上没有的 `pgrep`/`pkill`；tshark JSON 兼容嵌套协议对象、`--no-duplicate-keys` 与冒号分隔 hex body，并先判 response 再判 request，避免响应被当成幽灵请求。
- 安卓工具开关改为按对话独立：此前它写在一个全局的 DroidStore 标记里，一个对话打开「安卓」就会把 droid_*/apk_* 挂进所有打开的对话。现在每个会话有自己的 `zg-droid` 条目，输入框的开关只影响当前对话；切换回其他对话显示该对话自己的状态，刷新、重开与 fork 后保持不变。新对话默认关闭。
- 运行中的工具卡片（包括 `droid_shell`）现在和思考、bash 的单行一样在行首显示调用时间；此前实时卡片没有时间，只有结束后变成单行手风琴才出现。
- codemode 脚本里调用的工具（典型是 `droid_shell`）不再被当成独立的顶层工具卡片：这类内嵌调用没有自己的会话消息，实时卡片结束后无法收成单行手风琴，也不会随运行折叠，只有刷新后才消失。现在实时工具列表只接收顶层调用，内嵌调用由父工具的结果统一呈现。
- 漏洞中枢的证据文件从宿主路径取不到：Agent 用文件工具写脚本时拿到的是宿主项目目录（如 `/Users/.../.sentinel/projects/1018/build2.py`），`vuln_submit` 原样入库，界面预览却按容器路径只接受 `/work`，于是报「路径越界」。现在入库时把项目工作目录下的宿主路径归一成 `/work/...`，其他宿主路径直接拒绝并提示；已入库的旧记录在读取和预览时做同样的只读映射，只允许工作目录内，不会放宽到任意宿主文件
- Windows 单文件版打开网页一片空白，浏览器报 `Failed to load module script` / `MIME type "text/html"`：`serveStatic` 对 URL 路径用了平台相关的 `path.normalize`，Windows 把 `assets/app.js` 归一成 `assets\app.js`，而内嵌资源表以 `/` 为键，查不到就回退 `index.html`，脚本请求于是拿到 HTML。现在 URL 路径用 POSIX 归一化，`readWebuiFile` 查内嵌表前也把反斜杠转回 `/`；磁盘路径改用 `join`，不再手拼 `/`
- 新建工程后要刷新才出现在列表、指挥官对话要刷新才更新：`createEngine` 在插入后立即广播 `engine_update`，不再等指挥官的首个模型回合；服务端处理 `engine_create`/`engine_steer_commander` 不再阻塞该连接的后续消息；工程看板打开期间每 3 秒拉一次持久化的指挥官日志作为兜底，漏掉实时帧也不会停在旧内容
- 子代理面板原来固定只带最近 100 条，现在按每页 8 条翻页，更早的记录通过 `list_subagents` 的 `offset` 按需加载；工程任务会话的状态点与普通对话对齐：运行中是脉冲蓝点，完成后是空闲灰点（原来 `running` 没有样式、`done` 是绿点，正好看反）
- 新建项目后界面像没反应，刷新才看到新项目：创建/删除/重建容器这三个动作都由服务端广播 `projects` 表示成功、`error` 消息表示失败，但前端只接了失败那一条，成功时没人兑现 Promise——于是表单一直停在「创建中…」直到 60 秒超时。项目选择器在表单打开时会把项目列表整个藏起来，所以刚建好的项目根本看不见，只有刷新（表单状态重置）才露出来；删除确认框同样一直显示「删除中…」。现在 `projects` 广播也会兑现（[project-actions.ts](webui/src/project-actions.ts)，三处重复的 Promise 写法合并成一个 `ProjectAction`）
- `poc_search` 把「命中很多」说成「只有 100 条」：列表查询多取一行本来就是为了判断有没有被截断，但那一行取回来就被丢掉了，于是 30 万条的库上某个宽泛查询命中 5,000 条时，模型看到的是「POC 库 100 条匹配」，会据此以为库里只有这些模板。现在列表返回 `hasMore`，`poc_search` 在结果末尾明确写出「库中还有更多匹配未列出，请收窄查询」（两条提示都放在截断之外，列表本身撑爆预算时也还在）
- POC 导入的 zip 在超过 65535 个条目时被静默截断：真实条目数写在 zip64 目录记录里，而目录尾字段被填成 `0xFFFF`，读取代码只读那个 16 位字段——实测一个 7 万条目的压缩包被读成恰好 65535 条、`skipped` 为 0，也就是整库导入会「成功」地丢掉另外 22 万条模板，没有任何提示。现在会跟进 zip64 目录记录取真实条目数；确实用不了的 64 位单条目长度/偏移与加密条目改为按条跳过并回报原因，声明了 zip64 却没有该记录时直接报错，不再按 65535 截断。解压同时加上输出上限，避免一个小体积的 deflate 炸弹在体积检查之前先把内存打满
- 暂停目标的结束徽标不再挂在对话最底部：`pauseGoal` 从不写 `endedAt`，于是前端「目标结束后是否有新对话」的判断永远为假，暂停徽标一直留在最下面，总耗时还用 `Date.now()` 兜底越涨越大。暂停现在写入 `endedAt`（恢复时清掉），前端对旧会话回退到 `updatedAt`，操作员在目标结束后继续对话即不再显示该徽标
- 人工标记「已完成 / 已忽略」在会话列表里看不出来：行内的状态竖条只画了「待跟进 / 进行中」两种，标了这两个终态的行和没标记的一模一样，像是没保存；现在四种状态都画竖条（橙/蓝/绿/灰），并且两个终态在行尾直接写出「已完成 / 已忽略」。另外列表的悬浮卡只存了会话对象的快照，选完状态卡片仍显示旧值（点「已完成」后卡片还停在「未设置」，要靠移开鼠标重新悬停才刷新），改成按路径每帧查活的行数据
- 会话状态标记「有的不能用」：状态选择器固定在触发按钮下方 `rect.bottom + 5`，会话列表最后几行的面板下半部分落到视口外，「已完成 / 已忽略」点不到——空间不够时现在向上翻；另外面板在列表悬浮卡下方，鼠标移出卡片（去点面板）会触发卡片 150ms 后卸载、面板跟着消失，卡片现在在选择器打开期间保持显示
- 钉钉通知两处：loop-guard 的「输出重复已中止」不再触发运行报告推送（原来每次复读中止都发一条「运行已中止」，连续重复时刷屏）；漏洞高危推送按记录去重——提交时自评 high/critical 已推过，审查模型校准后维持 high/critical 会原样再推一条一模一样的（第 268 行 onSettled 不查是否推过），现在同一条记录只推一次，只有被审查模型抬级到 high/critical 且未推过的才补推
- 持续目标：loop-guard 的「输出重复已中止」不再占用轮数，也不再把目标暂停——那一次尝试退回预算（回合记录保留、标记为 aborted），由 loop-guard 自己的「换个思路」提示接管当轮，它结束后目标正常开下一轮并带完整契约；连续 3 次输出重复中止才暂停目标（新暂停原因「输出重复」），避免模型反复复读时无限制烧钱。手动中止的行为不变：照旧暂停目标。同时修掉一个结算账目问题：回合关闭后，后续结算（比如 loop-guard 的 nudge 回合）不会再把已关闭回合的结果与用量覆盖重算
- loop-guard 之前从未在控制台会话里生效：`createSessionContext` 只挂载 codemode / tool_search / MCP 三个扩展工厂，loop-guard 不在其中（也没有从 SDK 导出），于是任何复读都拦截不到——现存会话里出现单条消息 4 万+ 字符、同一行重复 3000+ 次而没有任何 `zg-loop-guard` 记录。现在 SDK 导出 `createLoopGuardExtension`，控制台在每个会话（含子代理）都挂载它；检测器同时补上两个盲区：同一行与其他行交替出现（连续计数永远建不起来，改为按行累计总数）和同一行内多个短语无固定周期轮换（新增尾部窗口的三词词组频率扫描）

- token「吊销」改为删除后旧记录仍永久留在列表里：上一版把吊销实现成 `DELETE`，但数据库里早先被标记 `revoked_at` 的行既不会被删掉，页面又只在未吊销的行上渲染「删除」按钮，那些行于是成了删不掉的死条目（本机 `pingban`、`lx` 两条即是）。`DroidStore` 打开时清掉带 `revoked_at` 的行，`revokedAt` 字段与 `revokeToken` 一并移除，协议消息 `droid_token_revoke` 改名 `droid_token_delete`，删除成为 token 唯一的退出语义
- DroidBridge「扫码填入」扫完没有任何反应：APK 用自定义的 `scanRequest = 42` 与 `onActivityResult` 的 requestCode 比对，而 zxing 的 `IntentIntegrator.initiateScan()` 固定用 `IntentIntegrator.REQUEST_CODE` 启动扫码页，两者永不相等，扫码结果被当成别人的结果直接丢弃。改为比对 `IntentIntegrator.REQUEST_CODE`。同时补上相机权限的重试：首次点按钮只申请权限、授予后原本什么都不做（要再点一次），现在 `onRequestPermissionsResult` 里授予即开扫、拒绝则提示

- 大文件推送会把手机上的 APP 打死：`droid_file_push` / `droid_frida_setup` 把整个文件 base64 后塞进**一帧** WS 消息（59MB 的 frida-server → 78.7MB），手机侧要同时持有 OkHttp 的消息缓冲、JSON 文本、取出的 base64 字符串和解码后的字节数组（manifest 没开 `largeHeap`，峰值 250MB 以上），进程被 OOM 杀掉、socket 断开，于是推送回报「设备连接已断开」——重试必然再杀一次。协议里的分片只做了设备→服务器方向（`data` 帧），服务器→设备的 `push` 一直是整包，`droid_file_push` 里那句「One frame per ~4MB keeps base64 under the gateway's message cap」描述的是没写出来的实现。现在 `push` 带 `seq` / `done`：网关按 1MB 原始字节切片、逐片 await 发送（`DroidGateway.pushFile`；`push` 同时从 `DroidRequestInput` 里排除，类型上就不允许再整包发），手机侧把分片追加写进应用私有缓存、`done` 时才搬到目标路径（应用 uid 写不了 `/data/local/tmp`，这一步经 su，与 `readFile` 读不到就走 root cat 同一个理由），协议里一直没生效的 `mode` 也真正落地（frida-server 直接以 0755 落盘）。顺带在 `sendFrame` 这个唯一出口加了单帧大小校验：超过 8MB 直接拒绝，不再有第二次把手机打死的机会

- DroidBridge 反连「一直断开重连」刷屏：`WsClient` 的重连循环里那道闩是给「等这条连接真的断开」用的，但放行条件写成了 `if (current == null) disconnected.countDown()`，而 `current` 只在 `onOpen` 里赋值——`newWebSocket` 是异步的，它返回时 `onOpen` 必然还没跑，所以这句**每次都立即放行**，循环根本不等断开，睡 1s 就再拨一条新连接（`onOpen` 又把退避重置回 1s，于是稳定在每秒一条）。网关收到新连接的 hello 会按「新连接顶掉旧连接」把旧的用 4003 关掉，手机侧就是每秒「在线 → 已关闭」闪一次，控制台日志也每秒一对「设备上线/设备离线」。现在这句提前放行删掉了，闩只由 `onFailure`/`onClosed` 放行；`newWebSocket` 同步抛错（地址非法等）改为捕获后退避重试，而不是把重连线程带走
- DroidBridge 的 rooted 探测会占住 OkHttp 的回调线程：`Shell.rootAvailable()` 在 `onOpen` 里同步跑（3 次 `su -c id -u`、每次 10s 超时，第一次还要等 Magisk 弹窗），而这条线程同时负责读 pong，堵住它就会让 `pingInterval(20s)` 超时，把一条健康的连接判成「sent ping but didn't receive pong」——su 慢的机器上每次连上约 20s 后必掉。现在探测与 hello 一起挪到后台线程，回调线程只负责收帧；心跳也改成 hello 发出去之后才启动（先发 hb 会被网关以 4001「handshake required」关闭），通知栏在 hello 发出前显示「连接中/握手中」而不是「在线」
- 重复反连：`DroidService.connect()` 每次被 `onStartCommand` 调用都新建一个 `WsClient` 且不停掉旧的（`start` 按钮每点一次就是一次），于是两条连接抢同一个 deviceId、被网关用 4003 互相顶掉，同样是「断开重连」刷屏。现在新建前先 `close()` 旧 client；状态上报也加了「只有当前这条连接的起落才更新」的判断，被顶掉的旧 socket 稍后关闭时不会再往通知栏写「已关闭」。顺带把心跳/hello 线程里的 `send` 包上 try/catch：`close()` 会关掉 OkHttp 的 dispatcher，晚到的 send 抛 `RejectedExecutionException`，线程里未捕获的异常会把整个进程带走

- `droid_file_pull` 拉大文件会把手机上的 DroidBridge 打死（现象是 app 在设置里显示「已停止」、通道回报「设备连接已断开」）：设备侧 `streamBytes` 是 `bytes.toList().chunked(CHUNK).map { it.toByteArray() }`——先把整个文件 `readFile` 进内存，再切成装箱的 `List<Byte>`。20MB 的 APK 要摊 20MB 源数组 + 2100 万个引用（约 80MB）+ 77 个分片数组，**还没发出第一帧**就把堆顶穿（APK 没开 `largeHeap`），进程被系统杀掉，网关对在途请求只会回报「设备连接已断开」，重试必然再杀一次。现在设备侧改成流式：`Handlers.streamFile` 用双缓冲从 `FileInputStream` 读一片发一片（稳态只占约 1MB），发送前用 `WebSocket.queueSize()` 做 4MB 水位背压（OkHttp 的发送队列没有上限，慢链路上不背压就等于把整个文件排进内存），`maxBytes` 改成边读边算（原来是读完才检查，等于没防）；服务端 `droid_file_pull` 用 `onData` 边收边写 fd，网关在挂了 `onData` 时不再同时累积一份，失败或空文件会删掉半截文件。`screencap` 也走同一条流式路径
- `droid_file_pull` 拉 root-only 文件（`/data/data/…`、`/system/priv-app/…`）拿到的是坏字节：兜底分支把 `su -c cat` 的输出经 `Shell.run` 当**字符串**收（8KB 一块各自 UTF-8 解码，跨块边界的多字节序列会被拆坏），再 base64 编解码一次「还原」字节，非法 UTF-8 字节全部变成 `EF BF BD`。现在直接读 `su cat` 的原始 stdout 字节流，不再经字符串和 base64 往返
- 设备进程被冻结时网关一直报「在线」，每个工具调用白等一整轮超时：Android（实测是 MuMu 模拟器）可以把 DroidBridge 整个进程 `SIGSTOP`——36 个线程全停在 `do_signal_stop`、`ps` 状态 `T`，但内核里 TCP 连接仍是 ESTABLISHED，于是 socket 不断、心跳停了、任何请求都永远等不到 `result`。网关此前只按「socket 在不在」判在线，操作员看到设备「在线」，模型则一条命令等 30-50s 超时后重试，实测一次 11 分钟的冻结让一轮渗透测试白等 6 分钟，还在结论里猜成「目标 provider 卡住」。现在网关带心跳看门狗：45s（心跳 15s，等于连丢 3 次）收不到任何帧就把设备标成无响应，`droid_devices` 写出「无响应（已 Ns 无心跳，进程可能被冻结）」并给出唤醒提示，`pickDevice` 与 `request` / `pushFile` / `openTunnel` 一律快速失败（不再把请求发进黑洞），在途请求立即以「设备无响应」结束；`droid_state` 带上 `stale` / `idleMs` 供设备页显示。冻结解除后进程在**同一条 socket** 上恢复心跳，第一帧到达即自动清除标记、无需重连。门限与扫描间隔可用 `DroidGatewayOptions` 覆盖（测试用 120ms 跑完冻结-恢复全过程）

- 设置 → 模型 页的两个渲染问题：`.settings input` 的 `width:100%` 把复选框也拉成整行宽的空白圆角条，方框本身看不见——守门的「MCP 工具判定」「纳入插件工具」两个开关因此整块看着像没渲染，角色卡的「自动评审」与模型编辑器的「清除已保存的密钥」同样受影响（改为 `input[type="checkbox"]` 复位为 inline-block）；`.settings label` 的 `display:block` 特异性压过 `.role-card__auto` 的 flex，该行也从未生效。守门面板还是 560px 窄列，与上方满宽的模型库之间分段线断成两截，改用 `settings--wide` 并对齐间距、去掉页头下重复的分隔线
- 审批页两个标签页的计数随当前标签一起被过滤：统计请求带着当前 tab 的 `approval` 过滤，于是切到「自动审批」时「AI 审批」的角标被打成 0、两个标签都显示 0，整条切换器看着像坏的（而这两个计数本该是导航，不是筛选结果）。`gate_audit_stats` 回复新增 `tabCounts`——其余过滤条件照算、只把 `approval` 摘掉的三个分桶计数；空状态也分成「这个桶还没有任何记录」（附什么模式下才会产生记录）与「筛选后没有符合条件的记录」两种说法

- POC 库导入大压缩包时页面长时间停在「导入中」：浏览器把整个文件读成 base64 塞进一帧 WebSocket，服务端再同步解压、逐条写库，文件一大就同时顶住传输、事件循环和前端状态；任何一步失败都没有入口把「导入中」复位。现在改为每个文件一条 HTTP 流式上传（请求体直接落临时文件，上限 512MB），返回任务 id 后由前端轮询进度，服务端在后台队列里异步导入、每 100 条让出事件循环，并在结束时统一刷新库；上传/任务失败、页面重连都会恢复按钮。另加压缩包解压后总量上限，避免高压缩比归档把内存和事件循环拖死
- 工程暂停后的僵尸对话：暂停只中止「正在流式」的 worker，而 worker 从登记为运行中到第一次 `prompt` 之间要建会话、连扩展、写目标契约（秒级），暂停落在这个窗口时 `abort()` 看到的是 `session === undefined`，只结算不阻止启动，任务随后照常跑完一整轮——看板写着已暂停，那条任务对话却在容器里无门禁执行、不进轮次与用量、事件也不再上报，恢复后 `continue_task` 还可能被「任务会话仍在运行」挡回来。现在 `EngineWorker` 有显式取消标志：`abort()`/`dispose()` 立即置位，`start()` 拿到会话后、以及每一轮 `prompt`/自动续跑之前都先检查，已取消就只记录会话 id 供恢复使用、不再投递；abort 也改为中止「非空闲」会话，压缩中的会话不再漏掉。指挥官同样不再是漏网之鱼：暂停/终止/删除时都中止它的回合并清空已排队的提示词，`promptCommander` 的循环在工程离开 running 后停止投递，启动失败的 catch 也不再覆盖暂停/终止写入的状态

- 多项目并行时的串项目：会话的项目上下文原来放在运行时全局字段里，工具在调用时才读「当前查看的项目」，于是切走之后原会话继续跑时，capture/droid/ios 的容器与工作目录、资产与 Web 搜索的证据和查询流水、子代理归属、业务建模记录都会落到正在看的项目上；droid/ios 的守门还会用当前查看会话的模式判定（B 是自动执行时，A 的后台设备命令会免审），运行报告与漏洞通知的项目名也取自当前项目。现在建会话时就把 projectId / 项目名 / 容器 / 工作目录 / 命令模式固定在会话上，上述工具与通知全部按调用会话解析；审批的「总是允许前缀」改为按项目分桶，在一个项目里放行的前缀不再覆盖另一个项目的同类命令。
- 修复设备页的「在线」不可信：控制台重启后，之前在线的设备会一直显示在线（数据库里的标记没人清）；设备进程被挂起或非正常断开时也一样。现在网关启动时清零所有在线标记（此刻不可能有连接），安卓设备页与 iOS 页一样把「无响应（心跳超时）」视为不在线，汇总计数同步。
- 设置 → POC 订阅打开时不读取订阅源：页面此前只在点「刷新」时发送 `list_poc_sources`，打开后看到的永远是空表，必须在别处触发过推送才有数据；现在进入页面即读取。设置 → Web 搜索的额度条在服务端只回套餐文字、没有 `usage` 数字时会被画成满格（0 / 1000 也显示满条），现在没有数字就不画进度条，只有 `remaining / limit` 或 `usage` 时才显示比例。

### Removed

- iOS IPA 源码、构建脚本与发布说明已移除：不再维护 `App/`、`scripts/build-ipa.sh` 和 TrollStore 受限模式；设备端只发 deb，配对由本地 setup 页完成。

- 设备页的「扫码即连」卡片：它把当前反连地址与**首个** token 拼成二维码、随地址或 token 变化自动重画，等于替操作员挑了一条 token——多台设备时扫到的可能不是要连的那台，页面上也没有任何地方写明用的是哪一条。二维码现在只从令牌列表按 token 生成：点某一行的「二维码」弹出该 token 的接入二维码（内容 = 当前反连地址 + 该 token），不点就没有二维码；接入指引第 1 步改为指向这个入口，卡片下方那行自动拼接「地址?token=首个token」的文本也一并去掉

### Fixed

- iOS daemon 的连接日志现在带上端口：之前 `connecting to ws://host/path` 把端口吃掉，排查反连时看不出目标端口。
- 隧道容器的解析器根本传不进去，WireGuard 档案因此建不出作业容器：`docker run --dns` 与 `--network container:` 不能同时用（Docker 直接报 `conflicting options: dns and the network mode`），而隧道档案的 DNS 是必填项，所以每次创建都用这个组合、每次都失败（`容器创建失败：conflicting options: dns and the network mode`）；`addProject` 与 `recreateProject` 这两条重建路径更是压根没把 DNS 传下去。现在改成把隧道 DNS 写成 `<配置目录>/proxy/<id>.resolv.conf`，以 `-v <文件>:/etc/resolv.conf:ro` 挂进作业容器：挂载写在 HostConfig 里，`docker start` 之后依然生效，改内容对运行中的容器下一次解析就可见，而 sidecar 自己继续用 Docker 内嵌 DNS（否则它解析不了 VPN 网关的主机名）。DNS 值按 IP 校验（多个用逗号或空格分隔，每个地址一行 `nameserver`），填了非 IP 直接报错，而不是写出一份 glibc 解析不了的 resolv.conf。
- iOS `--with-deps` 改为逐个 apt 安装 tcpdump/appinst：之前一条命令里 appinst 不存在会连累 tcpdump。
- iOS daemon 截屏失败时给出可操作原因（daemon 无 UI 会话，iOS 16 真机 `_UICreateScreenUIImage` 返回 nil），不再只报“空图片”。
